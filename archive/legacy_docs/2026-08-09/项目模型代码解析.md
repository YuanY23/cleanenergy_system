# 园区综合能源系统模型代码解析

本报告对当前园区综合能源系统（Integrated Energy System, IES）的优化调度模型代码进行全面回顾与深度解析。模型基于 **混合整数线性规划（Mixed-Integer Linear Programming, MILP）** 方法，利用 Python 优化建模库 **Pyomo** 构建，并调用成熟的双精度求解器 **HiGHS**（通过 `appsi_highs` 接口）进行高效求解。

本解析将详细阐述系统的数学建模方法论、三大能量平衡、各核心设备（电池储能、电解槽、储氢罐、燃料电池、热泵、燃气锅炉等）的物理与数学约束、设备参数的分段线性化处理方法、场景配置与敏感性分析框架，并对重要代码段进行逐行深度讲解。

---

## 一、 数学建模方法论：为什么使用混合整数线性规划（MILP）？

综合能源系统的优化调度问题通常涉及连续性的决策（如各时刻的充放电功率、产氢量、买电量等）以及离散性的状态（如设备的开/关机状态、储能系统充/放电状态的互斥限制等）。

本模型选择 **混合整数线性规划（MILP）** 这一主流方法来构建调度模型。

### 1. MILP 方法的优势
* **全局最优解保证**：与非线性规划（NLP）或启发式算法（如遗传算法、粒子群算法等）不同，MILP 属于凸优化或可以通过分支定界法（Branch and Bound）、割平面法（Cutting Planes）等数学手段在有限步内收敛到全局最优解的范畴。它不存在陷入局部最优解的风险，能够为决策提供绝对的基准参考。
* **计算效率极高，求解器生态成熟**：现代 MILP 求解器（如开源的 HiGHS，商业的 Gurobi、CPLEX 等）技术极为先进。对于本系统中 24 小时（步长 1 小时）的短周期日调度问题，MILP 模型通常可以在几十毫秒到几秒内求出精确解，极其适合嵌入到实际的能量管理系统（EMS）或进行大规模的参数敏感性分析扫描。
* **离散逻辑与开关约束的完美表达**：通过 0-1 二进制决策变量（Pyomo 中的 `Binary` 域），模型可以精确描述设备是开还是关、蓄电池在任意时刻只能充电或放电等物理排他逻辑。

### 2. MILP 方法的劣势与应对策略
* **物理非线性的近似误差**：真实的综合能源系统中存在大量非线性物理过程。例如：
  * 电解槽与燃料电池的效率随负荷率变化而呈现非线性（甚至非凸）变化；
  * 热泵的成绩系数（COP）随环境温度与供热温度差呈非线性关系；
  * 电池的老化折旧速度随充放电深度及吞吐量呈非线性递增。
* **应对策略（分段线性化与时序参数化）**：为了保留 MILP 的高效求解能力，模型引入了**分段线性化（Piecewise Linearization）**技术。将电解槽和燃料电池的效率特性、电池的老化成本曲线拆分为多个线性段，利用分段常数斜率来逼近非线性函数；对于热泵 COP，则将其作为已知的时间序列参数预先录入，避开了模型内的非线性乘积项。

## 二、 核心能量平衡约束与代码逐行解析

系统在运行过程中必须在每一个小时（时间步 $t$）内严格维持**电力平衡**、**热力平衡**和**氢气平衡**。

### 1. 电力平衡约束

#### (1) 物理与数学公式原理
电力平衡基于**基尔霍夫电流定律（KCL）**的能量守恒表达。在任意时刻 $t$，系统内的所有“电源侧”电能之和必须等于“负荷/耗能侧”电能之和：
$$P_{\text{grid\_buy}, t} + P_{\text{pv\_used}, t} + P_{\text{wind\_used}, t} + P_{\text{battery\_discharge}, t} + P_{\text{fuel\_cell}, t} = P_{\text{electric\_load}, t} + P_{\text{heat\_pump}, t} + P_{\text{battery\_charge}, t} + P_{\text{electrolyzer}, t}$$

* **左侧（电能流入）**：电网购电、自用光伏发电、自用风电、电池放电、燃料电池发电。
* **右侧（电能流出）**：园区基础电负荷、热泵耗电、电池充电、电解槽耗电。

#### (2) 代码解析
代码位于 [constraints_power.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_power.py#L34-L52) 的 `add_power_balance_constraints` 函数中：

```python
def power_balance_rule(m, t):
    # 电力平衡：电源侧等于电负荷、热泵耗电、充电和电解槽耗电。
    return (
        m.grid_buy[t]
        + m.pv_used[t]
        + m.wind_used[t]
        + m.battery_discharge[t]
        + m.fuel_cell_power[t]
        == m.electric_load[t]
        + m.heat_pump_power[t]
        + m.battery_charge[t]
        + m.electrolyzer_power[t]
    )

model.power_balance_constraint = Constraint(model.T, rule=power_balance_rule)
```

**逐行及参数解析**：
* `m.grid_buy[t]`：决策变量（连续非负），时刻 $t$ 从外部大电网购买的电功率 ($\text{kW}$)。
* `m.pv_used[t]`、`m.wind_used[t]`：决策变量（连续非负），时刻 $t$ 实际消纳的光伏和风电功率 ($\text{kW}$)。
* `m.battery_discharge[t]`：决策变量（连续非负），时刻 $t$ 电池的放电功率 ($\text{kW}$)。
* `m.fuel_cell_power[t]`：决策变量（连续非负），时刻 $t$ 燃料电池的发电功率 ($\text{kW}$)。
* `m.electric_load[t]`：模型参数，时刻 $t$ 园区固定的基础用电负荷 ($\text{kW}$)。
* `m.heat_pump_power[t]`：决策变量（连续非负），时刻 $t$ 电制热泵消耗的电功率 ($\text{kW}$)。
* `m.battery_charge[t]`：决策变量（连续非负），时刻 $t$ 电池的充电功率 ($\text{kW}$)。
* `m.electrolyzer_power[t]`：决策变量（连续非负），时刻 $t$ 电解槽消耗的电功率 ($\text{kW}$)。
* `model.T`：集合，时间步集合（如 24 小时，即 $0 \dots 23$）。

### 2. 热力平衡约束

#### (1) 物理与数学公式原理
热力平衡基于**热力学第一定律（能量守恒）**。在园区供热系统中，为了维持室内温度或工业热需求，任意时刻 $t$ 供热设备的供热量必须与热负荷完全相等：
$$Q_{\text{heat\_pump}, t} + Q_{\text{gas\_boiler}, t} = Q_{\text{heat\_load}, t}$$

* **供热源**：电制热泵供热量 $Q_{\text{heat\_pump}, t}$、燃气锅炉供热量 $Q_{\text{gas\_boiler}, t}$。
* **热需求**：园区总热负荷 $Q_{\text{heat\_load}, t}$。

#### (2) 代码解析
代码位于 [constraints_heat.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_heat.py#L46-L50) 的 `add_heat_constraints` 函数中：

```python
def heat_balance_rule(m, t):

```

**逐行及参数解析**：
* `m.heat_pump_heat[t]`：决策变量（连续非负），时刻 $t$ 热泵输出的供热功率 ($\text{kW}$)。
* `m.gas_boiler_heat[t]`：决策变量（连续非负），时刻 $t$ 燃气锅炉输出的供热功率 ($\text{kW}$)。
* `m.heat_load[t]`：模型参数，时刻 $t$ 园区固定的热负荷需求 ($\text{kW}$)。

### 3. 氢气平衡约束

#### (1) 物理与数学公式原理
氢气平衡基于**质量守恒定律**。在任意时刻 $t$，进入园区氢气管网的总氢气质量流量必须与出管网的氢气流量达到动态平衡：
$$m_{\text{h2\_production}, t} + m_{\text{h2\_discharge}, t} + m_{\text{h2\_external\_supply}, t} = m_{\text{hydrogen\_load}, t} + m_{\text{h2\_charge}, t} + m_{\text{h2\_sale}, t} + m_{\text{h2\_fuel\_cell}, t}$$

* **左侧（氢气流入）**：本地电解水制氢量 $m_{\text{h2\_production}, t}$、储氢罐放氢量 $m_{\text{h2\_discharge}, t}$、外部高价补氢量 $m_{\text{h2\_external\_supply}, t}$（兜底用）。
* **右侧（氢气流出）**：园区基础氢负荷 $m_{\text{hydrogen\_load}, t}$、储氢罐充氢量 $m_{\text{h2\_charge}, t}$、对外售氢量 $m_{\text{h2\_sale}, t}$、燃料电池消耗氢气量 $m_{\text{h2\_fuel\_cell}, t}$。

#### (2) 代码解析
代码位于 [constraints_hydrogen.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_hydrogen.py#L154-L161) 中的 `add_hydrogen_constraints` 函数中：

```python
def hydrogen_balance_rule(m, t):
    # 氢气平衡：制氢、放氢和外部补氢满足氢负荷、充氢、售氢和燃料电池耗氢。
    return (
        m.h2_production[t] + m.h2_discharge[t] + m.h2_external_supply[t]
        == m.hydrogen_load[t] + m.h2_charge[t] + m.h2_sale[t] + m.h2_fuel_cell[t]
    )
```

**逐行及参数解析**：
* `m.h2_production[t]`：决策变量（连续非负），时刻 $t$ 电解槽产氢量 ($\text{kg/h}$)。
* `m.h2_discharge[t]`：决策变量（连续非负），时刻 $t$ 从储氢罐中释放出的氢气量 ($\text{kg/h}$)。
* `m.h2_external_supply[t]`：决策变量（连续非负），时刻 $t$ 外部紧急补氢量 ($\text{kg/h}$)。用于防范本地制氢能力不足导致模型无解。
* `m.hydrogen_load[t]`：模型参数，时刻 $t$ 园区的氢负荷需求 ($\text{kg/h}$)。
* `m.h2_charge[t]`：决策变量（连续非负），时刻 $t$ 注入储氢罐的氢气量 ($\text{kg/h}$)。
* `m.h2_sale[t]`：决策变量（连续非负），时刻 $t$ 对外销售的氢气量 ($\text{kg/h}$)。
* `m.h2_fuel_cell[t]`：决策变量（连续非负），时刻 $t$ 燃料电池所消耗的氢气量 ($\text{kg/h}$)。

## 三、 核心设备物理与运行约束深度解析

### 1. 电池储能系统（BESS）约束

电池储能模型的建模重点是其**荷电状态（State of Charge, SOC）**的时序演化关系，以及防止同时充放电的互斥逻辑。

#### (1) SOC 状态演化与终端一致性约束
根据物理规律，当前时刻 $t$ 结束时电池所存的能量等于上一时刻结束时的能量加上当前时刻充入的能量（考虑充电效率 $\eta_{\text{ch}}$）减去放出的能量（考虑放电效率 $\eta_{\text{dis}}$）：
$$E_{\text{soc}, t} = E_{\text{soc}, t-1} + P_{\text{charge}, t} \cdot \eta_{\text{ch}} \cdot \Delta t - \frac{P_{\text{discharge}, t}}{\eta_{\text{dis}}} \cdot \Delta t$$
在 $t=0$ 时，其初始值由 $E_{\text{initial}}$ 确定。此外，为了防止优化模型在优化的最后一刻（如第 23 小时）将电池里的电全部放空来降低当天的成本（这会导致第二天无法循环），需要设置**终端 SOC 必须等于初始 SOC** 的约束：
$$E_{\text{soc}, T} = E_{\text{initial}}$$

代码解析（来自 [constraints_storage.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_storage.py#L33-L57)）：

```python
def battery_soc_rule(m, t):
    # SOC 表示每个小时结束后的电池电量。
    previous_soc = m.battery_initial_soc if t == 0 else m.battery_soc[t - 1]
    return (
        m.battery_soc[t]
        == previous_soc
        + m.battery_charge[t] * m.battery_eta_ch
        - m.battery_discharge[t] / m.battery_eta_dis
    )

model.battery_soc_constraint = Constraint(model.T, rule=battery_soc_rule)

def battery_terminal_rule(m):
    # 末端 SOC 等于初始 SOC，避免模型把电池最后放空。
    return m.battery_soc[m.T.last()] == m.battery_initial_soc

model.battery_terminal_constraint = Constraint(rule=battery_terminal_rule)
```
* `m.battery_eta_ch` 和 `m.battery_eta_dis` 分别是电池的充、放电效率（小于1的常数，如 0.95）。
* 当 $t=0$ 时，上一个状态引用 `m.battery_initial_soc` 参数。
* `m.T.last()` 返回集合中的最后一个索引（23），限制该时刻的 SOC 必须强制等于 `m.battery_initial_soc`。

#### (2) 充放电互斥与上限约束
在任意时刻 $t$，电池的充电功率与放电功率都不能超过其额定最大值 $P_{\max}$，并且不能**同时充放电**。模型通过引入两个二进制决策变量 `is_battery_charging` ($u_{\text{ch}, t}$) 和 `is_battery_discharging` ($u_{\text{dis}, t}$) 实施以下约束：
$$P_{\text{ch}, t} \le u_{\text{ch}, t} \cdot P_{\max}$$
$$P_{\text{dis}, t} \le u_{\text{dis}, t} \cdot P_{\max}$$
$$u_{\text{ch}, t} + u_{\text{dis}, t} \le 1, \quad u_{\text{ch}, t}, u_{\text{dis}, t} \in \{0, 1\}$$

代码解析（来自 [constraints_storage.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_storage.py#L11-L31)）：

```python
def battery_charge_limit_rule(m, t):
    # 充电功率受额定功率和充电状态共同限制。
    return m.battery_charge[t] <= m.is_battery_charging[t] * m.battery_power_max

model.battery_charge_limit_constraint = Constraint(model.T, rule=battery_charge_limit_rule)

def battery_discharge_limit_rule(m, t):
    # 放电功率受额定功率和放电状态共同限制。
    return m.battery_discharge[t] <= m.is_battery_discharging[t] * m.battery_power_max

model.battery_discharge_limit_constraint = Constraint(model.T, rule=battery_discharge_limit_rule)

def battery_exclusive_rule(m, t):
    # 同一小时不能同时充电和放电。
    return m.is_battery_charging[t] + m.is_battery_discharging[t] <= 1

model.battery_exclusive_constraint = Constraint(model.T, rule=battery_exclusive_rule)
```
* 如果不加互斥约束，在某些分时电价相同或为零的时刻，模型为了降低碳排放或平衡多余电量，可能会控制电池**同时以最大功率充电和放电**。这在物理上是不合理的，且会因充放电效率的损失造成无谓的能量消纳，因此必须使用 0-1 变量进行逻辑互斥。

### 2. 氢能系统设备约束

#### (1) 电解槽最小载荷率与容量约束
电解水制氢设备（电解槽）在运行时，耗电功率不能超过额定最大值，且如果处于开启状态，其功率不能低于最小运行载荷限制（防止低负荷下运行不稳定或效率过低）：
$$P_{\text{elec}, t} \le u_{\text{elec}, t} \cdot P_{\text{elec\_max}}$$
$$P_{\text{elec}, t} \ge u_{\text{elec}, t} \cdot P_{\text{elec\_max}} \cdot r_{\text{elec\_min\_rate}}$$

代码解析（来自 [constraints_hydrogen.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_hydrogen.py#L11-L29)）：

```python
def electrolyzer_capacity_rule(m, t):
    # 电解槽耗电功率受额定功率和运行状态共同限制。
    return m.electrolyzer_power[t] <= m.is_electrolyzer_on[t] * m.electrolyzer_power_max

model.electrolyzer_capacity_constraint = Constraint(model.T, rule=electrolyzer_capacity_rule)

def electrolyzer_min_load_rule(m, t):
    return (
        m.electrolyzer_power[t]
        >= m.is_electrolyzer_on[t]
        * m.electrolyzer_power_max
        * m.electrolyzer_min_load_rate
    )

model.electrolyzer_min_load_constraint = Constraint(model.T, rule=electrolyzer_min_load_rule)
```
* `m.is_electrolyzer_on[t]`：二进制决策变量 ($0$ 或 $1$)，表示时刻 $t$ 电解槽是否开机。
* `m.electrolyzer_min_load_rate`：参数，例如 $0.2$，代表最小允许运行载荷为 $20\%$。

#### (2) 储氢罐（H2 Storage Tank）状态演化约束
储氢罐具有类似电池 SOC 的时序累积效应。同时，考虑到氢气分子极小、易于从金属缝隙中渗透，储氢罐通常存在微量自放氢（自泄漏）。其储氢量 $M_{\text{storage}, t}$ 的变化规律为：
$$M_{\text{storage}, t} = M_{\text{storage}, t-1} \cdot (1 - \alpha) + m_{\text{charge}, t} - m_{\text{discharge}, t}$$
其中 $\alpha$ 是每小时的氢气泄漏率。

代码解析（来自 [constraints_hydrogen.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_hydrogen.py#L163-L181)）：

```python
def h2_storage_rule(m, t):
    # 储氢量表示每个小时结束后的储氢库存。
    previous_storage = m.h2_storage_initial if t == 0 else m.h2_storage[t - 1]
    return (
        m.h2_storage[t]
        == previous_storage * (1 - m.h2_storage_loss_rate_per_hour)
        + m.h2_charge[t]
        - m.h2_discharge[t]
    )

model.h2_storage_constraint = Constraint(model.T, rule=h2_storage_rule)
```
* `m.h2_storage_loss_rate_per_hour` ($\alpha$)：每小时储氢损失系数（如 $0.001$）。
* 储氢罐的容量上限受硬约束限制：`m.h2_storage[t] <= m.h2_storage_capacity`。

### 3. 供热侧设备物理约束

#### (1) 电制热泵（Heat Pump）与 COP
热泵通过消耗电能将低温热源搬运至高温侧，其产热功率与耗电功率成正比，比例为成绩系数（Coefficient of Performance, COP）：
$$Q_{\text{hp}, t} = P_{\text{hp}, t} \cdot \text{COP}_t$$

由于 COP 通常随环境温度变化而改变，在代码中它被作为随时间步 $t$ 改变的输入参数 `m.heat_pump_cop[t]` 处理，使该约束保持为线性：

```python
def heat_pump_conversion_rule(m, t):
    # 热泵供热量等于耗电功率乘以 COP。
    return m.heat_pump_heat[t] == m.heat_pump_power[t] * m.heat_pump_cop[t]
```

同时，热泵的运行受最大耗电容量、是否可用比例以及场景开关的综合限制：
$$P_{\text{hp}, t} \le u_{\text{hp\_on}, t} \cdot P_{\text{hp\_max}} \cdot r_{\text{hp\_available}, t}$$
```python
def heat_pump_capacity_rule(m, t):
    # 热泵耗电功率不能超过额定功率；是否可运行由场景开关控制。
    return (
        m.heat_pump_power[t]
        <= m.is_heat_pump_on[t]
        * m.heat_pump_power_max
        * m.heat_pump_available_ratio[t]
    )
```

#### (2) 燃气锅炉与天然气消耗热值转换

$$F_{\text{gas}, t} = \frac{Q_{\text{boiler}, t}}{\eta_{\text{boiler}} \cdot \text{LHV}_{\text{gas}}}$$
其中 $\eta_{\text{boiler}}$ 是锅炉热效率，$\text{LHV}_{\text{gas}}$ 是天然气低位发热值（Lower Heating Value，单位为 $\text{kWh/m}^3$）。

## 四、 设备非线性特性的分段线性化（Piecewise Linearization）

分段线性化是 MILP 处理非线性特性的核心方法。下面深度剖析**电解槽/燃料电池效率变化**与**电池老化成本**的分段线性化实现。

### 1. 电解槽与燃料电池的功率-效率分段线性化

#### (1) 数学建模原理
电解槽的效率（产生一公斤氢气所需要的电量，即 $\text{kWh/kg}$）在不同运行负荷下是不同的，这导致“产氢量 - 电功率”曲线是非线性的。

为了在 MILP 中表达这种非线性：
1. 将电解槽总运行功率范围 $[0, P_{\max}]$ 划分为 $N$ 个区间。
2. 每一段 $s \in \{1 \dots N\}$ 具有固定的宽度比例 $\Delta_s$ 以及对应的效率值 $\text{kWh\_per\_kg}_s$。
3. 引入每一时间步、每一分段的辅助连续决策变量 $P_{\text{segment}, t, s}$，代表电解槽在分段 $s$ 上分配到的功率。
4. 约束条件限制每一段的功率：
   $$0 \le P_{\text{segment}, t, s} \le P_{\max} \cdot \Delta_s$$
   $$P_{\text{total}, t} = \sum_{s=1}^N P_{\text{segment}, t, s}$$
5. 每一段对应的产氢量为：
   $$m_{\text{prod\_segment}, t, s} = \frac{P_{\text{segment}, t, s}}{\text{kWh\_per\_kg}_s}$$
   $$m_{\text{total\_production}, t} = \sum_{s=1}^N m_{\text{prod\_segment}, t, s}$$

因为求解器为了降低成本，会优先分配效率最高（即每公斤耗电最少）的功率分段。燃料电池的“耗氢量 - 发电功率”分段线性化原理完全对称。

#### (2) 代码解析（电解槽分段）
代码位于 [constraints_hydrogen.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_hydrogen.py#L31-L81)：

```python

        m.electrolyzer_power[t]

            m.electrolyzer_power_segment[t, segment]
            for segment in m.ELECTROLYZER_SEGMENTS
```

### 2. 电池老化折旧成本的分段线性化

电池充放电的累积吞吐量（Throughput）会加剧电池化学介质的老化。通常，当每天的循环充放电量较低时，老化成本较低；而当频繁大功率循环（如深度充放电）时，老化折旧成本呈非线性急剧上升。

#### (1) 数学建模原理
为了使电池在日调度优化中自动克制无意义的频繁充放电，模型引入了基于凸折旧曲线的分段线性老化成本模型：
1. 每一时刻 $t$ 的总吞吐量定义为：
   $$T_t = P_{\text{charge}, t} + P_{\text{discharge}, t}$$
2. 将总吞吐量投影到不同的老化区间 $s$ 上：
   $$T_t = \sum_{s} T_{t, s}$$
   $$0 \le T_{t, s} \le E_{\max} \cdot \Delta_{\text{degrad}, s}$$
3. 在目标函数中对每一分段的吞吐量施加递增的折旧单价 $C_{\text{degrad}, s}$（满足凸性质：$C_{\text{degrad}, 1} < C_{\text{degrad}, 2} < \dots$）。
4. 在最小化目标函数的驱动下，求解器会**自动优先使用便宜的老化段**（因为它的折旧单价低），当且仅当套利空间极高、需要更大充放电功率时，才会进入高成本的老化段。这种**凸成本分段线性化**无需引入任何二进制状态变量即可被单纯形法天然正确求解。

#### (2) 代码解析
代码位于 [constraints_storage.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_storage.py#L59-L83)：

```python
def battery_degradation_throughput_rule(m, t):
    # 充放电总功率之和被拆分到各个吞吐量分段中
    return (
        sum(
            m.battery_degradation_throughput_segment[t, segment]
            for segment in m.BATTERY_DEGRADATION_SEGMENTS
        )
        == m.battery_charge[t] + m.battery_discharge[t]
    )

model.battery_degradation_throughput_constraint = Constraint(
    model.T, rule=battery_degradation_throughput_rule
)

def battery_degradation_segment_limit_rule(m, t, segment):
    # 每一段吞吐量受限于该段宽度率与电池容量的乘积
    return (
        m.battery_degradation_throughput_segment[t, segment]
        <= m.battery_degradation_segment_width_rate[segment]
        * m.battery_energy_max
    )

model.battery_degradation_segment_limit_constraint = Constraint(
    model.T,
    model.BATTERY_DEGRADATION_SEGMENTS,
    rule=battery_degradation_segment_limit_rule,
)
```

该分段的折旧费用在 [objective.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/objective.py#L19-L23) 的总运行成本目标函数中进行累加：

## 五、 碳核算、碳税与碳配额上限建模

### 1. 碳排放实时核算
系统的碳排放分为两部分：
1. **间接排放（Scope 2）**：购电产生的间接碳排放。每个时间步的购电量乘以该时刻电网的动态碳排放因子 $EF_{\text{grid}, t}$。
2. **直接排放（Scope 1）**：燃气锅炉燃烧天然气产生的直接碳排放。消耗的天然气量乘以天然气固有的碳排放因子 $EF_{\text{gas}}$。

$$\text{Carbon}_{t} = P_{\text{grid\_buy}, t} \cdot EF_{\text{grid}, t} + F_{\text{gas}, t} \cdot EF_{\text{gas}}$$

代码解析（来自 [constraints_carbon.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_carbon.py#L11-L19)）：
```python
def carbon_emission_rule(m, t):
    # 碳排放 = 外购电间接排放 + 天然气燃烧直接排放。
    return (
        m.carbon_emission[t]
        == m.grid_buy[t] * m.grid_emission_factor[t]
        + m.gas_consumption[t] * m.gas_emission_factor
    )

model.carbon_emission_constraint = Constraint(model.T, rule=carbon_emission_rule)
```

### 2. 碳配额硬约束与松弛兜底机制（Soft Constraint）
为了响应低碳政策，限制系统的日总碳排放量不得超过给定的碳上限 $C_{\text{cap}}$：
$$\sum_{t} \text{Carbon}_{t} \le C_{\text{cap}}$$
然而，在一些极端天气（如无风无光且负荷极高）下，为了保障园区的用能安全，系统必须购电或烧气，此时如果死守碳上限，会导致数学模型**直接无解（Infeasible）**。

为了避免无解，模型引入了**松弛变量（Slack Variable）/超额碳排放变量** $C_{\text{excess}}$，将硬约束转化为“软约束”：
$$\sum_{t} \text{Carbon}_{t} \le C_{\text{cap}} + C_{\text{excess}}, \quad C_{\text{excess}} \ge 0$$
并在目标函数中，对该超额碳排放施加极其高昂的罚值（如 10000.0 元/kgCO2）：
$$\text{Cost}_{\text{penalty}} = C_{\text{excess}} \cdot \text{Penalty}_{\text{carbon\_cap}}$$

代码解析（来自 [constraints_carbon.py](file:///E:/clean_engry_system/src/zero_carbon_park/models/constraints_carbon.py#L21-L26)）：
```python
def carbon_cap_rule(m):
    # 日总碳排放不能超过上限；若目标过严，则用超额变量记录缺口并施加高惩罚。
    return sum(m.carbon_emission[t] for t in m.T) <= m.carbon_emission_cap + m.carbon_cap_excess

model.carbon_cap_constraint = Constraint(rule=carbon_cap_rule)
```

## 六、 场景分析与敏感性分析框架设计

基于底层统一的园区物理拓扑与约束逻辑，系统通过“布尔场景开关”与“数据乘数扰动”相结合的方式，在无需重构物理公式的前提下实现不同递进场景（S0-S5）的动态软切换以及多维参数敏感性分析。

### 1. S0 - S5 场景设计与设备开关逻辑

#### (1) 物理与数学公式原理
为了实现“一套物理拓扑，多套业务场景”的设计，避免为每个场景编写冗余的运行约束，模型引入场景布尔开关的数值化转换。不同设备的最大容量限制参数均由标称最大参数乘以场景使能开关得到：
$$P_{\text{hp, max}} = P_{\text{hp, kW}} \cdot \gamma_{\text{hp}}$$
$$P_{\text{battery, max}} = P_{\text{battery, kW}} \cdot \gamma_{\text{battery}}$$

| $P_{\text{battery, kW}}$ | `device["battery_power_kW"]` | 电池标称额定最大充放电电功率 | $\ge 0$ 的非负实数 | $\text{kW}$ |

### 2. 敏感性分析（Sensitivity Analysis）的扰动实现

#### (1) 物理与数学公式原理
敏感性分析用于探测外部环境对优化决策的扰动规律。对于峰谷电价差敏感性分析，首先对输入的时间序列电价进行筛选，提取出其中的最大值（峰电价）和最小值（谷电价），然后乘上扰动系数：
$$p_{\text{valley}, t} = p_{\text{valley, 0}} \cdot \lambda_{\text{valley\_price\_scale}}, \quad \forall t \in \mathcal{T}_{\text{valley}}$$
$$p_{\text{peak}, t} = p_{\text{peak, 0}} \cdot \lambda_{\text{peak\_price\_scale}}, \quad \forall t \in \mathcal{T}_{\text{peak}}$$
其中，时序电价中判定峰谷区间的判断表达式（掩码条件）为：
$$\mathcal{T}_{\text{valley}} = \{ t \in T \mid p_{t} = \min_{\tau \in T} \{ p_{\tau} \} \}$$
$$\mathcal{T}_{\text{peak}} = \{ t \in T \mid p_{t} = \max_{\tau \in T} \{ p_{\tau} \} \}$$

#### (2) 公式中各参数与变量含义
| 参数/变量符号 | 代码/Pyomo对应名称 | 物理含义 | 取值范围 | 单位 |
| :--- | :--- | :--- | :--- | :--- |
| $p_t$ | `timeseries["electricity_price_cny_per_kwh"]` | 时序电价数组中时刻 $t$ 的电价 | $\ge 0$ 的非负实数 | 元/kWh |
| $p_{\text{valley, 0}}$ | `valley_price` | 基准最低（谷）电价 | $\ge 0$ 的非负实数 | 元/kWh |
| $p_{\text{peak, 0}}$ | `peak_price` | 基准最高（峰）电价 | $\ge 0$ 的非负实数 | 元/kWh |
| $\lambda_{\text{valley\_price\_scale}}$ | `case.changes["valley_price_scale"]` | 谷电价拉伸/压缩扰动比例 | $[0.5, 2.0]$ | 无量纲 |
| $\lambda_{\text{peak\_price\_scale}}$ | `case.changes["peak_price_scale"]` | 峰电价拉伸/压缩扰动比例 | $[0.5, 2.0]$ | 无量纲 |
| $p_{\text{valley}, t}$ | `timeseries.loc[valley_mask, ...]` | 扰动后时刻 $t$ 的谷电价 | $\ge 0$ 的非负实数 | 元/kWh |
| $p_{\text{peak}, t}$ | `timeseries.loc[peak_mask, ...]` | 扰动后时刻 $t$ 的峰电价 | $\ge 0$ 的非负实数 | 元/kWh |

#### (3) 代码解析
代码位于 [sensitivity.py](file:///E:/clean_engry_system/src/zero_carbon_park/scenarios/sensitivity.py#L318-L433)：
```python

    prices = timeseries["electricity_price_cny_per_kwh"]
    valley_price = prices.min()

    if "valley_price_scale" in case.changes:

    if "peak_price_scale" in case.changes:
        peak_mask = prices == peak_price
        timeseries.loc[peak_mask, "electricity_price_cny_per_kwh"] = (
            timeseries.loc[peak_mask, "electricity_price_cny_per_kwh"]
            * case.changes["peak_price_scale"]
        )
```

## 七、 容量规划（Capacity Planning）模型与多典型日架构

容量规划在数学上是一个混合整数线性规划（MILP）问题。它的目标是协同优化系统的设备建设装机容量（第一阶段 Here-and-Now 决策，即一次性 CAPEX）以及全年的运行调度费用（第二阶段 Wait-and-See 决策，即 OPEX 与需量电费），从而求得生命周期成本最低的最优规划方案。

### 1. 设备容量决策变量与边界约束

#### (1) 物理与数学公式原理
设备容量规划决策变量属于非负实数域，最大值取决于场地物理制约或变压器可用最大容量限制：
$$0 \le C_{i} \le C_{i, \max}, \quad \forall i \in \mathcal{P}_{\text{devices}}$$
其中 $\mathcal{P}_{\text{devices}}$ 为待优化的 8 类规划设备的集合，决策变量在优化求解过程中根据系统平衡与经济性指标自动优化选择装机数值。

#### (2) 公式中各参数与变量含义
| 变量/参数符号 | 代码/Pyomo对应名称 | 物理含义 | 取值范围 | 单位 |
| :--- | :--- | :--- | :--- | :--- |
| $C_{\text{wind}}$ | `model.wind_capacity_kw` | 风电装机容量决策变量 | $[0, 30000]$ | $\text{kW}$ |
| $C_{\text{pv}}$ | `model.pv_capacity_kw` | 光伏装机容量决策变量 | $[0, 30000]$ | $\text{kW}$ |
| $P_{\text{bat\_cap}}$ | `model.battery_power_capacity_kw` | 电池最大充放电功率决策变量 | $[0, 15000]$ | $\text{kW}$ |
| $E_{\text{bat\_cap}}$ | `model.battery_energy_capacity_kwh` | 电池最大蓄电量决策变量 | $[0, 60000]$ | $\text{kWh}$ |
| $P_{\text{elec\_cap}}$ | `model.electrolyzer_power_capacity_kw` | 电解槽最大输入电功率决策变量 | $[0, 10000]$ | $\text{kW}$ |
| $M_{\text{h2\_tank\_cap}}$ | `model.h2_storage_capacity_kg` | 储氢罐最大储氢质量决策变量 | $[0, 5000]$ | $\text{kg}$ |

### 2. 年化资本回收系数（CRF）的推导与年化 CAPEX 计算

#### (1) 物理与数学公式原理
设备的原始投资（CAPEX）是一次性的资金支出，而运行维护成本是以年为周期发生。为了使这两项开支能够在目标函数中直接累加优化，引入资本回收系数（Capital Recovery Factor, CRF），将投资费用等额分摊至使用寿命内的每一年。
资本回收系数（CRF）公式为：
$$\text{CRF}_{i} = \frac{r(1+r)^{N_i}}{(1+r)^{N_i} - 1}$$
当年度折现率 $r = 0$ 时，公式退化为平均年限折旧：
$$\text{CRF}_{i} = \frac{1}{N_i}$$
年化后的单位容量投资单价：
$$c_{\text{annual}, i} = c_{\text{unit}, i} \cdot \text{CRF}_{i}$$
年化总投资成本（CAPEX）计算公式：
$$C_{\text{CAPEX}} = \sum_{i} C_{i} \cdot c_{\text{annual}, i}$$
具体展开如下：
$$C_{\text{CAPEX}} = C_{\text{wind}} \cdot c_{\text{wind\_capex\_annual}} + C_{\text{pv}} \cdot c_{\text{pv\_capex\_annual}} + P_{\text{bat\_cap}} \cdot c_{\text{bat\_p\_capex\_annual}} + E_{\text{bat\_cap}} \cdot c_{\text{bat\_e\_capex\_annual}} + P_{\text{elec\_cap}} \cdot c_{\text{elec\_capex\_annual}} + M_{\text{h2\_tank\_cap}} \cdot c_{\text{h2\_tank\_capex\_annual}} + P_{\text{fc\_cap}} \cdot c_{\text{fc\_capex\_annual}} + P_{\text{hp\_cap}} \cdot c_{\text{hp\_capex\_annual}}$$

#### (2) 公式中各参数与变量含义
| 参数/变量符号 | 代码/Pyomo对应名称 | 物理含义 | 取值范围 | 单位 |
| :--- | :--- | :--- | :--- | :--- |
| $r$ | `cost_params.discount_rate` | 年折现率 | $[0.0, 1.0]$，默认为 $0.08$ | 无量纲 |
| $N_i$ | `cost_params.*_life_years` | 设备 $i$ 的设计使用寿命年限 | $\ge 1$ 整数 | 年 |
| $c_{\text{unit}, i}$ | `cost_params.*_capex_cny_per_kw` | 设备 $i$ 的原始投资建设单位价格 | $> 0$ 的非负实数 | 元/kW (或元/kWh, 元/kg) |
| $c_{\text{annual}, i}$ | `model.*_capex_annual_cny_per_kw` | 设备 $i$ 年化后的单位容量投资单价 | $> 0$ 的非负实数 | 元/kW·年 (或元/kWh·年, 元/kg·年) |
| $C_{\text{CAPEX}}$ | `model.annualized_investment_cost` | 系统年化总投资成本（表达式） | $\ge 0$ 的非负实数 | 元/年 |

规划中各设备的默认使用年限 $N_i$ 与初始单位投资单价 $c_{\text{unit}, i}$ 分别为：

### 3. 多典型日权重机制与年度 OPEX 计算

#### (1) 物理与数学公式原理
为了在计算时保留 24 小时精细的时序运行特征，同时降低一整年（8760小时）寻优的庞大决策维度，系统引入了多典型日权重机制。取 $D$ 个典型日，每一典型日 $d \in D$ 在全年有对应的代表天数权重 $W_d$，且满足 $\sum_{d} W_d = 365$。
年化运行成本（OPEX）为各典型日内 24 小时运行费用的加权求和，数学公式为：
$$C_{\text{OPEX}} = \sum_{d \in D} W_d \sum_{t \in T} C_{\text{hourly}, d, t}$$
其中，每个小时的运行费用 $C_{\text{hourly}, d, t}$ 包含：
- **外购电费用**：$P_{\text{grid\_buy}, d, t} \cdot p_{\text{buy}, d, t}$
- **天然气费用**：$F_{\text{gas}, d, t} \cdot p_{\text{gas}, d, t}$
- **弃风弃光惩罚费用**：$(P_{\text{pv\_curtail}, d, t} + P_{\text{wind\_curtail}, d, t}) \cdot c_{\text{curtail}}$
- **碳排放税费**：$m_{\text{carbon}, d, t} \cdot p_{\text{carbon}, d, t}$
- **电池功率运维费**：$(P_{\text{bat\_ch}, d, t} + P_{\text{bat\_dis}, d, t}) \cdot c_{\text{bat\_om}}$
- **电池老化折旧费（分段线性化部分）**：$\sum_{s} T_{\text{degrad}, d, t, s} \cdot c_{\text{degrad}, s}$
- **电解槽基本运维费**：$m_{\text{h2}, d, t} \cdot c_{\text{elec\_om}}$
- **外部兜底紧急补氢费**：$m_{\text{h2\_ext}, d, t} \cdot c_{\text{h2\_ext}}$
- **燃料电池常规运维费**：$P_{\text{fc}, d, t} \cdot c_{\text{fc\_om}}$
- **电网售电收益（作为负项扣除）**：$- P_{\text{grid\_sell}, d, t} \cdot p_{\text{sell}, d, t}$，其中售电功率定义为自用风光溢出功率售卖给电网的数值，即 $P_{\text{grid\_sell}, d, t} = P_{\text{pv\_sold}, d, t} + P_{\text{wind\_sold}, d, t}$。

```python
    return sum(
        m.weight_days[d]
        * sum(
            m.grid_buy[d, t] * m.grid_price[d, t]
            + m.gas_consumption[d, t] * m.gas_price[d, t]
            + (m.pv_curtail[d, t] + m.wind_curtail[d, t]) * m.curtail_penalty
            + m.carbon_emission[d, t] * m.carbon_price[d, t]
            + (m.battery_charge[d, t] + m.battery_discharge[d, t]) * m.battery_om
            + sum(
                m.battery_degradation_throughput_segment[d, t, segment]
                * m.battery_degradation_segment_cost[segment]
                for segment in m.BATTERY_DEGRADATION_SEGMENTS

            + m.h2_production[d, t] * m.electrolyzer_om
            + m.h2_external_supply[d, t] * m.h2_external_supply_cost
            + m.fuel_cell_power[d, t] * m.fuel_cell_om
            - m.grid_sell[d, t] * m.grid_sell_price[d, t]
            for t in m.T
        )
        for d in m.D
    )
```

### 4. 变压器需量电费与燃料电池应急备用容量价值计算

#### (1) 物理与数学公式原理
1. **需量电费**：变压器需量费是基于园区全年中自电网购电的最大功率征收的，限制了最大冲击功率：
   $$C_{\text{demand}} = P_{\text{import\_peak}} \cdot p_{\text{demand\_charge\_year}}$$
   在任意时刻，购电功率不得超过该需量值：
   $$P_{\text{import\_peak}} \ge P_{\text{grid\_buy}, d, t}, \quad \forall d \in D, \forall t \in T$$
2. **燃料电池应急备用容量价值**：对于燃料电池中作为园区应急备用而不参与常规调度的容量，获得年度折减补贴价值（等效于负的运营成本），以租金折返形式鼓励投资：
   $$V_{\text{fc\_backup}} = P_{\text{fc\_backup}} \cdot v_{\text{fc\_backup\_year}}$$
   该备用容量受到如下容量约束：
   $$P_{\text{fc\_backup}} \le P_{\text{fc\_cap}}$$
   $$P_{\text{fc\_backup}} \le P_{\text{fc\_reserve}}$$
   且要求燃料电池的装机功率必须大于硬性政策规定的最低容量阈值：
   $$P_{\text{fc\_cap}} \ge P_{\text{fc\_required}}$$

### 6. 新新能源可用性与消纳耦合硬约束

#### (1) 物理与数学公式原理
风光在容量规划中实际输出的电功率，必须与该典型日的气象条件（容量系数）以及优化的装机容量相耦合。对于每一典型日，风光可用总功率计算公式为：
$$P_{\text{pv\_used}, d, t} + P_{\text{pv\_sold}, d, t} + P_{\text{pv\_curtail}, d, t} = C_{\text{pv}} \cdot \text{cf}_{\text{pv}, d, t}, \quad \forall d \in D, \forall t \in T$$
$$P_{\text{wind\_used}, d, t} + P_{\text{wind\_sold}, d, t} + P_{\text{wind\_curtail}, d, t} = C_{\text{wind}} \cdot \text{cf}_{\text{wind}, d, t}, \quad \forall d \in D, \forall t \in T$$
且由于外部大电网并网接入限制，倒售电量存在上限硬约束限制：
$$P_{\text{grid\_sell}, d, t} = P_{\text{pv\_sold}, d, t} + P_{\text{wind\_sold}, d, t} \le P_{\text{export\_limit}}, \quad \forall d \in D, \forall t \in T$$

#### (2) 参数/变量含义与取值范围表格
| 符号 | 代码/Pyomo对应名称 | 物理含义 | 属性与取值范围 | 单位 |
| :--- | :--- | :--- | :--- | :--- |
| $\text{cf}_{\text{pv}, d, t}$ | `m.pv_cf[d, t]` | 气象时序提供光伏的容量系数 | 时序参数，$[0.0, 1.0]$ | 无量纲 |
| $\text{cf}_{\text{wind}, d, t}$ | `m.wind_cf[d, t]` | 气象时序提供风能的容量系数 | 时序参数，$[0.0, 1.0]$ | 无量纲 |

## 八、 固定容量不确定性压力测试机制

在得到基准容量规划结果后，系统需要对极端及不确定性时序工况进行检验，以评估当前配置方案在面对负荷波起时或新能源极低出力时的保供安全裕度、经济弹性与碳排波动情况。

### 1. 固定容量变量的数学原理与 Pyomo 实现

#### (1) 物理与数学公式原理
压力测试采取“容量锁定，只作调度”的思路，将第一阶段的 8 类设备装机容量强制固定：
$$C_{i} = C_{\text{baseline}, i}, \quad \forall i \in \mathcal{P}_{\text{devices}}$$
由于容量 $C_i$ 转化为常数，年度投资成本 CAPEX 亦降为常数，求解器将不对其进行优化更新，从而将问题降阶为仅包含运行费用最小化的调度调度寻优。

#### (2) 公式中各参数与变量含义
| 参数符号 | 代码/Pyomo对应名称 | 物理含义 | 取值范围 | 单位 |
| :--- | :--- | :--- | :--- | :--- |
| $C_{\text{baseline}, i}$ | `capacity[variable_name]` | 基准 `NORMAL` 规划中求得的最优装机容量 | $\ge 0$ | $\text{kW}$ (或 $\text{kWh}$, $\text{kg}$) |

### 2. 时序调度的重新优化与风险评估

#### (1) 物理与数学公式原理
1. **不确定性时序输入生成**：根据不确定性场景 $u$，将各典型日内的风光资源条件和各种负荷需求乘以各自的变动缩放因子：
   $$\text{cf}'_{k, d, t} = \text{cf}_{k, d, t} \cdot \lambda_{k, u}, \quad k \in \{\text{pv}, \text{wind}\}$$
   $$P'_{\text{load}, d, t} = P_{\text{load}, d, t} \cdot \lambda_{\text{load}, u}, \quad \text{load} \in \{\text{electric}, \text{heat}, \text{hydrogen}\}$$
2. **偏差与脆弱性量化**：
   在固定容量下重新优化出各个压力场景年度运行成本 $C_{\text{OPEX}, u}$，加上固定的 CAPEX 得到总成本 $C_{\text{total}, u}$，进而计算出指标相对 `NORMAL` 场景的偏差百分比：
   - 成本相比基准的增幅：
     $$\Delta C_{\text{cost}, u} = \frac{C_{\text{total}, u} - C_{\text{total}, \text{NORMAL}}}{C_{\text{total}, \text{NORMAL}}} \times 100\%$$
   - 碳排放相比基准的增幅：
     $$\Delta \text{Carbon}_{u} = \frac{\text{Carbon}_{\text{annual}, u} - \text{Carbon}_{\text{annual}, \text{NORMAL}}}{\text{Carbon}_{\text{annual}, \text{NORMAL}}} \times 100\%$$
   - 年度外部紧急补氢量：由于设备容量已被锁死，在供需矛盾激烈的扰动场景中，若本地制氢与储氢不足以自给，为了防止数学模型无解，系统需要采购高单价的外部补充氢气 $m_{\text{h2\_ext}, d, t}$，从而导致年度总补氢量显著上升。

#### (2) 公式中各参数与变量含义
| 变量/参数符号 | 代码/Pyomo对应名称 | 物理含义 | 取值范围与场景设定 | 单位 |

## 九、 场景概率加权随机容量规划（Stochastic Planning）

在不确定性存在的情况下，若仅用单一确定性预测做规划，得到的容量可能会偏于乐观，导致在遇到波动时运行成本极高。两阶段场景概率加权随机容量规划（Two-stage Stochastic Programming）在规划阶段就将概率分布引入决策中，实现平均期望成本最低。

### 1. 两阶段随机优化模型架构

#### (1) 物理与数学公式原理
1. **第一阶段决策变量（装机容量决策 $C_{i}$）**：属于 Here-and-Now 变量。设备装机容量必须在气象与负荷条件未知时预先确定，因此容量变量在所有运行运行场景中必须**一致且唯一共享**：
   $$C_{d, u, i} = C_{i}, \quad \forall d \in D, \forall u \in U$$
2. **第二阶段决策变量（时序调度决策 $X_{\text{operation}, d, u, t}$）**：属于 Wait-and-See 变量。当具体气象负荷场景 $u$ 发生后，调度控制可以在建好的设备基础上作针对性的运行调节调节，在各运行场景中是**相互独立**的：
   $$X_{\text{operation}, d, u, t} = \phi_t(\text{weather}_{d, u}, \text{load}_{d, u})$$
3. **两阶段约束耦合**：
   第一阶段的容量决策直接限制了第二阶段时序运行的出力上限与蓄能天花板，例如：
   $$P_{\text{battery\_charge}, d, u, t} \le P_{\text{bat\_cap}}, \quad \forall d, u, t$$
   $$E_{\text{battery\_soc}, d, u, t} \le E_{\text{bat\_cap}}, \quad \forall d, u, t$$

---

### 2. 复合场景构建与概率权重归一化

#### (1) 物理与数学公式原理
为了在时序上模拟全年的天气，同时在事件空间上表达概率波动，模型对典型日 $D$ 与不确定性场景 $U$ 进行笛卡尔积运算，生成 $D \times U$ 个复合场景（共 18 个复合随机典型日）。
每个复合场景 $(d, u)$ 分配的权重天数公式为：
$$W_{d, u} = W_{d} \cdot \tilde{p}_{u}$$
其中 $\tilde{p}_{u}$ 是不确定性场景 $u$ 的归一化概率：
$$\tilde{p}_{u} = \frac{p_{u}}{\sum_{k \in U} p_{k}}$$
当 $p_{u}$ 为已经归一化的发生概率时（其总和为 1），有 $\tilde{p}_u = p_u$。所有复合场景的权重天数之和依旧满足全年天数要求：
$$\sum_{d \in D} \sum_{u \in U} W_{d, u} = \sum_{d \in D} W_d \sum_{u \in U} \tilde{p}_u = 365 \cdot 1.0 = 365$$

#### (2) 公式中各参数与变量含义
| 场景 ID | 物理含义与名称 | 发生概率 $p_u$ | 概率取值范围 |
| :--- | :--- | :--- | :--- |
| `NORMAL` | 正常预测场景 | $0.50$ | $[0.0, 1.0]$ |
| `PV_LOW` | 光伏偏低场景 | $0.12$ | $[0.0, 1.0]$ |
| `WIND_LOW` | 风电偏低场景 | $0.12$ | $[0.0, 1.0]$ |
| `LOAD_HIGH` | 电热负荷偏高场景 | $0.10$ | $[0.0, 1.0]$ |
| `H2_HIGH` | 氢负荷偏高场景 | $0.08$ | $[0.0, 1.0]$ |
| `EXTREME` | 风光低负荷高极端场景 | $0.08$ | $[0.0, 1.0]$ |

### 3. 期望总成本最小化目标函数

#### (1) 物理与数学公式原理
随机容量规划致力于优化确定一套容量，以使得年化投资成本（CAPEX）与数学期望年度运行成本（Expected OPEX）之和为最小：
$$\min \quad C_{\text{stochastic}} = C_{\text{CAPEX}} + \sum_{u \in U} \tilde{p}_u \left[ \sum_{d \in D} W_d \sum_{t \in T} C_{\text{hourly}, d, u, t} + C_{\text{demand}, u} - V_{\text{fc\_backup}, u} \right]$$
若将复合权重天数 $W_{d, u} = W_{d} \cdot \tilde{p}_{u}$ 代入上式：
$$C_{\text{stochastic}} = C_{\text{CAPEX}} + \sum_{u \in U} \sum_{d \in D} W_{d, u} \left[ \sum_{t \in T} C_{\text{hourly}, d, u, t} + \text{Demand\_Term}_{d, u} - \text{Backup\_Term}_{d, u} \right]$$
由此可见，在数学表达式上，复合后的目标函数形式与基准多典型日容量规划的求和框架完全同构，仅是索引天数集进行了拓扑展开。因此，在代码中可以直接复用常规优化的目标函数构建规则。

## 十、 最坏情形下鲁棒容量规划（Robust Planning）

如果随机容量规划追求的是“全局期望概率最优”，鲁棒容量规划（Robust Capacity Planning）则基于运筹学极小化极大（Min-Max）的思路，牺牲部分常规场景下的经济性，来确保系统在最极端场景下的总成本不会失控，从而保证系统在极高风险偏好下的保供安全性。

### 1. 极小化极大（Min-Max）数学模型与线性化转换

#### (1) 物理与数学公式原理
鲁棒容量规划的数学目标是：寻找最优容量，使年化投资成本（CAPEX）加上最坏不确定性场景下的年度运行成本（OPEX）之和最小：
$$\min \quad \left( C_{\text{CAPEX}} + \max_{u \in U} \{ C_{\text{OPEX\_annual}, u} \} \right)$$
以及 $C_{\text{OPEX\_annual}, u}$ 是不确定性场景 $u$ 发生时的年化运行成本：
$$C_{\text{OPEX\_annual}, u} = \sum_{d \in D} W_d \sum_{t \in T} C_{\text{hourly}, d, u, t} + C_{\text{demand}, u} - V_{\text{fc\_backup}, u}$$
注意，此处的典型日权重天数 $W_d$ 没有乘以概率，即假设不确定性场景 $u$ 发生了完整的一年。
为了消除 $\max$ 非线性算子，引入一个辅助决策变量 $Z$（代表最坏情形下的年度总成本），将非线性规划转化为完全等价的线性不等式约束组：
$$\min \quad Z$$
同时，对各个场景 $u \in U$ 的年度总成本设置上界约束：
$$Z \ge C_{\text{CAPEX}} + C_{\text{OPEX\_annual}, u}, \quad \forall u \in U$$
随着求解器最小化 $Z$，不等式约束将被推至紧绷状态，迫使辅助变量 $Z$ 恰好等于最恶劣的那个场景的总成本。这实现了原 Min-Max 问题在 **100% 线性**空间下的严谨求解。

#### (2) 公式中各参数与变量含义
| 变量/表达式符号 | 代码/Pyomo对应名称 | 物理含义 | 属性与取值范围 | 单位 |
| :--- | :--- | :--- | :--- | :--- |
| $Z$ | `model.worst_case_total_cost` | 最坏情形年度总成本辅助变量 | 决策变量，连续非负 $\ge 0$ | 元 |
| $C_{\text{OPEX\_annual}, u}$ | `model.robust_case_operation_cost[u]` | 时序模拟场景 $u$ 年化运行成本 | 表达式，$\ge 0$ | 元 |
| $C_{\text{total\_annual}, u}$ | `model.robust_case_total_cost[u]` | 年化投资成本与年化运行成本之和 | 表达式，$\ge 0$ | 元 |

---

### 2. 代码实现解析

#### (1) 物理与数学公式原理
为了实现上述线性化重构，代码需要：
1. 停用基准单场景/期望目标函数 `model.annual_total_cost`；
2. 定义不确定性场景集合 $U$ 及其辅助决策变量 $Z$；
3. 为每个场景 $u \in U$ 创建独立的年度时序运行成本表达式，再与 $C_{\text{CAPEX}}$ 相加定义年化总成本表达式；
4. 建立下界约束 $Z \ge C_{\text{CAPEX}} + C_{\text{OPEX\_annual}, u}$ 并设定最小化 $Z$ 为新目标。

#### (2) 代码解析
在代码 [robust_planning.py](file:///e:/clean_engry_system/src/zero_carbon_park/uncertainty/robust_planning.py#L112-L161) 中，重构目标函数的逻辑如下：
```python
def _add_worst_case_objective(model, robust_days) -> None:
    # 建立场景与复合随机典型日的映射
    case_day_ids = {}
    for config, _ in robust_days:
        case_day_ids.setdefault(config.uncertainty_case_id, []).append(config.day_id)
    case_ids = list(case_day_ids)

    # 1. 钝化常规容量规划的直接总成本目标函数
    model.annual_total_cost.deactivate()
    
    # 2. 声明场景集 model.U 与鲁棒总成本辅助变量 model.worst_case_total_cost (即 Z)
    model.U = Set(initialize=case_ids, ordered=True)
    model.worst_case_total_cost = Var(domain=NonNegativeReals)

    # 3. 构造子函数，计算单个场景在 365 天内的年化运行成本（此处未乘概率）
    def daily_operation_cost(m, d):
        return sum(
            m.grid_buy[d, t] * m.grid_price[d, t]
            + m.gas_consumption[d, t] * m.gas_price[d, t]
            + (m.pv_curtail[d, t] + m.wind_curtail[d, t]) * m.curtail_penalty
            + m.carbon_emission[d, t] * m.carbon_price[d, t]
            + (m.battery_charge[d, t] + m.battery_discharge[d, t]) * m.battery_om
            + sum(
                m.battery_degradation_throughput_segment[d, t, segment]
                * m.battery_degradation_segment_cost[segment]
                for segment in m.BATTERY_DEGRADATION_SEGMENTS
            )
            + m.h2_production[d, t] * m.electrolyzer_om
            + m.h2_external_supply[d, t] * m.h2_external_supply_cost
            + m.fuel_cell_power[d, t] * m.fuel_cell_om
            - m.grid_sell[d, t] * m.grid_sell_price[d, t]
            for t in m.T
        )

    def robust_case_operation_cost_rule(m, u):
        return sum(m.weight_days[d] * daily_operation_cost(m, d) for d in case_day_ids[u])

    model.robust_case_operation_cost = Expression(
        model.U,
        rule=robust_case_operation_cost_rule,
    )

    # 4. 构造场景总成本表达式：年化投资 + 对应场景 of 年化运行成本
    def robust_case_total_cost_rule(m, u):
        return m.annualized_investment_cost + m.robust_case_operation_cost[u]

    model.robust_case_total_cost = Expression(model.U, rule=robust_case_total_cost_rule)

    # 5. 添加最坏情形约束：Z >= Total_u 限制辅助变量的下边界
    def worst_case_cost_rule(m, u):
        return m.worst_case_total_cost >= m.robust_case_total_cost[u]

    model.worst_case_cost_constraint = Constraint(model.U, rule=worst_case_cost_rule)
    
    # 6. 设置新的优化目标，最小化辅助变量 Z
    model.robust_objective = Objective(expr=model.worst_case_total_cost, sense=minimize)
```

## 十一、 总结

当前园区综合能源系统模型代码具有以下特点：
1. **多能耦合**：基于热力学与电工学定律，精细耦合了“电-热-氢”三种能量流；
2. **逻辑严密**：通过 0-1 变量表达设备启停与储能充放量互斥，避免了物理不合理现象；
3. **线性逼近非线性**：使用分段常数单耗（电解槽/燃料电池）和分段折旧单价（电池老化）实现了非线性物理过程的高效线性化近似；
4. **鲁棒性（防无解）设计**：在碳排放上限和氢负荷满足性上设置了软约束（松弛变量 + 极高惩罚），即使在极端参数配置下模型也绝对可解，并在结果中直观暴露出容量或配额缺口。
5. **不确定性规划支持**：支持固定容量的压力测试（Stress Test）、两阶段场景概率加权随机规划（Stochastic Planning）以及最坏情形下鲁棒容量规划（Robust Planning），满足在不同风险偏好下的工程容量方案比选。
