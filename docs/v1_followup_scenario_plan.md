# v1 后续场景研究计划

> 版本：v1.1 草案  
> 日期：2026-06-16  
> 状态：仅作为后续场景规划，暂不执行代码修改。

## 1. 当前 v1 基础状态

当前项目已经跑通 S0-S5 六个基础场景：

| 场景 | 含义 | 当前作用 |
|---|---|---|
| S0 | 电网购电 + 燃气锅炉 | 传统供能基准 |
| S1 | S0 + 风电光伏 | 检验新能源接入价值 |
| S2 | S1 + 电池储能 | 检验电储能削峰填谷和消纳作用 |
| S3 | S2 + 电解槽 + 储氢罐 + 氢负荷 | 检验电-氢耦合 |
| S4 | S3 + 热泵 + 燃料电池 | 完整电-热-氢-储系统 |
| S5 | S4 + 碳价 | 低碳调度场景 |

后续 v1 不建议直接跳到全年 8760 小时或复杂随机优化。建议继续保持 24 小时典型日，先把场景体系做完整，形成可以解释的研究结论。

## 2. 后续场景总体原则

1. 优先做不改变 MILP 数学结构的场景，只调整输入参数和设备容量。
2. 每一类场景只回答一个研究问题，避免所有因素一起变化导致结论说不清。
3. 每组场景都保留 S4 或 S5 作为对照基准。
4. 输出指标保持统一：总成本、购电量、弃风弃光量、碳排放、碳成本、电池循环量、制氢量、储氢利用率、燃料电池发电量。
5. 每完成一组场景，都生成独立 CSV、Excel、图片和简短结论。

## 3. 推荐执行顺序

### 阶段 1：参数敏感性场景

这个阶段不改模型结构，只改输入参数，适合优先完成。

#### 1.1 碳价敏感性场景

研究问题：碳价升高后，系统成本和碳排放如何变化。

建议场景：

| 场景 | 碳价 |
|---|---|
| C0 | 0 元/tCO2 |
| C1 | 30 元/tCO2 |
| C2 | 60 元/tCO2 |
| C3 | 100 元/tCO2 |
| C4 | 150 元/tCO2 |
| C5 | 200 元/tCO2 |

对照基准：S4 或 S5。

重点输出：

1. 碳价-总成本曲线。
2. 碳价-碳排放曲线。
3. 碳价-购电量曲线。
4. 碳价是否真正改变调度策略。

#### 1.2 新能源出力比例场景

研究问题：风光资源增加后，是否能降低成本和碳排放，是否会造成弃风弃光。

建议场景：

| 场景 | 风电和光伏可发功率倍率 |
|---|---|
| R0 | 0.6 |
| R1 | 0.8 |
| R2 | 1.0 |
| R3 | 1.2 |
| R4 | 1.5 |
| R5 | 2.0 |

重点输出：

1. 新能源倍率-总成本曲线。
2. 新能源倍率-弃风弃光量曲线。
3. 新能源倍率-新能源消纳率曲线。
4. 判断当前系统是否缺少储能或氢能消纳能力。

#### 1.3 电池容量敏感性场景

研究问题：电池容量增加是否继续有收益，是否存在边际收益下降。

建议场景：

| 场景 | 电池功率倍率 | 电池容量倍率 |
|---|---:|---:|
| B0 | 0.0 | 0.0 |
| B1 | 0.5 | 0.5 |
| B2 | 1.0 | 1.0 |
| B3 | 1.5 | 1.5 |
| B4 | 2.0 | 2.0 |
| B5 | 3.0 | 3.0 |

重点输出：

1. 电池容量-系统成本曲线。
2. 电池容量-弃电量曲线。
3. 电池容量-SOC 曲线。
4. 判断电池容量继续扩大是否值得。

#### 1.4 氢负荷敏感性场景

研究问题：园区氢需求变化后，电解槽和储氢罐是否能满足需求，成本如何变化。

建议场景：

| 场景 | 氢负荷倍率 |
|---|---:|
| H0 | 0.0 |
| H1 | 0.5 |
| H2 | 1.0 |
| H3 | 1.5 |
| H4 | 2.0 |

重点输出：

1. 氢负荷-总成本曲线。
2. 氢负荷-制氢量曲线。
3. 氢负荷-储氢罐最低库存。
4. 判断当前电解槽和储氢罐容量是否够用。

#### 2.3 电网排放因子场景

### 阶段 4：需要小幅扩展模型的运行策略场景

这个阶段开始引入新约束或新目标项，每次只加一个功能。

#### 4.1 售氢收益场景

研究问题：如果园区可以出售绿氢，电解槽是否更积极运行。

需要新增：

1. 售氢变量 `h2_sale[t]`。
2. 氢气平衡中加入售氢项。
3. 目标函数中加入售氢收益。

建议场景：

| 场景 | 售氢价格 |
|---|---:|
| HSAL0 | 0 元/kg |
| HSAL1 | 10 元/kg |
| HSAL2 | 20 元/kg |
| HSAL3 | 30 元/kg |
| HSAL4 | 40 元/kg |

重点输出：

1. 售氢价格-售氢量。
2. 售氢价格-电解槽利用小时。
3. 售氢价格-总收益和总成本。

#### 4.2 碳排放上限场景

研究问题：如果园区必须满足碳排放约束，成本会增加多少。

需要新增：

1. 日总碳排放上限参数。
2. 总碳排放约束。

建议场景：

|---|---:|
| CAP0 | 100% |
| CAP1 | 90% |
| CAP2 | 80% |
| CAP3 | 70% |
| CAP4 | 60% |

重点输出：

1. 碳约束强度-总成本曲线。
2. 碳约束强度-购电量变化。
3. 碳约束强度-天然气消耗变化。

#### 4.3 新能源消纳率约束场景

研究问题：强制提高新能源消纳率时，系统成本和储能/氢能运行如何变化。

需要新增：

1. 新能源消纳率约束。
2. 总新能源可发量和总弃电量统计。

建议场景：

| 场景 | 最低新能源消纳率 |
|---|---:|
| RC0 | 90% |
| RC1 | 95% |
| RC2 | 98% |
| RC3 | 99% |

重点输出：

1. 消纳率要求-总成本。
2. 消纳率要求-电池充放电。
3. 消纳率要求-制氢量。

### 阶段 5：典型日扩展场景

这个阶段用于提高研究可信度，但不建议早于前四个阶段。

#### 5.1 季节典型日场景

研究问题：冬季、夏季、过渡季的系统调度差异。

建议场景：

| 场景 | 含义 |
|---|---|
| TD_SUMMER | 夏季典型日 |
| TD_WINTER | 冬季典型日 |
| TD_TRANSITION | 过渡季典型日 |

需要数据：

1. 不同季节的电负荷。
2. 不同季节的热负荷。
3. 不同季节的风电和光伏可发功率。

重点输出：

1. 不同典型日成本对比。
2. 不同典型日碳排放对比。
3. 不同典型日设备利用率对比。

#### 5.2 多典型日加权年化场景

研究问题：用多个典型日估算全年运行成本和排放。

建议先设置：

| 典型日 | 年权重天数 |
|---|---:|
| 夏季典型日 | 120 |
| 冬季典型日 | 120 |
| 过渡季典型日 | 125 |

重点输出：

1. 年化运行成本。
2. 年化碳排放。
3. 年化新能源消纳率。

## 4. 建议的 v1 执行路线

### v1.1：先完成参数敏感性

优先顺序：

1. 碳价敏感性 C0-C5。
2. 新能源出力比例 R0-R5。
3. 电池容量 B0-B5。
4. 氢负荷 H0-H4。

完成后应得到第一批论文式结论：碳价、新能源、电池和氢负荷分别如何影响成本、排放和消纳。

### v1.2：完成价格与排放因子场景

优先顺序：

1. 电价峰谷差 P0-P4。
2. 天然气价格 G0-G4。
3. 电网排放因子 E0-E3。

完成后可分析市场价格和外部电网低碳化对园区调度的影响。

### v1.3：完成设备容量组合场景

优先顺序：

1. 电解槽容量 EL0-EL4。
2. 储氢罐容量 HS0-HS4。
3. 燃料电池容量 FC0-FC4。

完成后可判断当前设备容量配置是否合理。

### v1.4：加入小幅模型扩展

优先顺序：

1. 售氢收益。
2. 碳排放上限。
3. 新能源消纳率约束。

完成后模型从“运行成本最优”扩展到“政策约束和市场收益共同影响调度”。

### v1.5：扩展典型日

优先顺序：

1. 夏季典型日。
2. 冬季典型日。
3. 过渡季典型日。
4. 多典型日加权年化结果。

完成后研究结论会比单日 24 小时更稳健。

## 5. 暂缓到 v2 的内容

以下内容建议暂时不要放入 v1：

1. 8760 小时全年逐时优化。
2. 容量规划优化，即让模型同时决定设备容量。
3. 随机优化或鲁棒优化。
4. 多目标 Pareto 前沿。
5. 需求响应。
6. 储热系统。
7. Web 可视化界面。

原因是这些内容会明显增加模型复杂度。v1 的主要目标应当是让 24 小时综合能源系统的场景分析足够清晰、可解释、可复现。

## 6. 下一步建议

下一步建议先做 v1.1，不改数学模型，只扩展场景配置和批量运行能力。

v1.1 的最小实现目标：

1. 新增场景参数修改机制。
2. 支持一组场景批量运行。
3. 输出每组场景的汇总 CSV/Excel。
4. 输出每组场景的对比图。
5. 自动生成每组场景的结论 Markdown。

这样可以在当前模型稳定的基础上，最快得到有研究价值的对比结果。
