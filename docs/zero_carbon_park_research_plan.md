## 1. 当前已确认的方向

本项目第一阶段的目标，是先用典型模拟数据把综合能源系统仿真和优化调度完整跑通。后续如果你提供真实数据或新的研究要求，再在现有框架上替换数据、扩展模型和完善功能。

已确认决策如下：

1. 第一版直接采用 MILP，不再先做纯 LP 版本。
2. 第一版只做 24 小时日前优化，时间步长 1 小时。
3. 第一版使用典型模拟数据作为输入，后续再替换为新数据。
4. 求解器使用开源 HiGHS。
5. 交付形态先做命令行脚本 + CSV/Excel + 图片，不做 Web 页面。
6. 代码变量、函数、文件名使用英文。
7. 代码注释以中文为主，关键逻辑尽量逐行解释，方便学习。
8. 当前重点是保证风电、光伏、电网、电池、制氢、储氢、燃料电池、热泵、燃气锅炉、碳排放和场景分析能够跑通。

## 3. MILP 建模简述

### 3.1 优化目标

目标函数为系统总运行成本最小：

```text
min total_cost
  = grid_cost
  + gas_cost
  + operation_maintenance_cost
  + renewable_curtailment_penalty
  + carbon_cost
  - hydrogen_sale_revenue
```

第一版可以先保留 `hydrogen_sale_revenue` 的参数位置。如果暂时不做售氢，令售氢量为 0。

### 3.2 核心约束

电力平衡：

```text
风电利用 + 光伏利用 + 电网购电 + 电池放电 + 燃料电池发电
= 电负荷 + 电池充电 + 电解槽耗电 + 热泵耗电
```

热力平衡：

```text
热泵供热 + 燃气锅炉供热 = 热负荷
```

氢气平衡：

```text
电解槽制氢 + 储氢罐放氢
= 氢负荷 + 燃料电池耗氢 + 储氢罐充氢 + 售氢
```

新能源利用：

```text
风电利用 + 弃风 = 风电可发功率
光伏利用 + 弃光 = 光伏可发功率
```

电池 SOC：

```text
下一时刻SOC = 当前SOC + 充电量 * 充电效率 - 放电量 / 放电效率
```

储氢罐状态：

```text
下一时刻储氢量 = 当前储氢量 + 充氢量 - 放氢量
```

### 3.3 MILP 中的二进制变量

第一版直接做 MILP，因此会加入必要的二进制变量。

建议优先加入：

1. 电池充电状态 `is_battery_charging[t]`。
2. 电池放电状态 `is_battery_discharging[t]`。
3. 电解槽运行状态 `is_electrolyzer_on[t]`。
4. 燃料电池运行状态 `is_fuel_cell_on[t]`。

对应约束：

```text
is_battery_charging[t] + is_battery_discharging[t] <= 1
p_battery_charge[t] <= is_battery_charging[t] * battery_charge_power_max
p_battery_discharge[t] <= is_battery_discharging[t] * battery_discharge_power_max
```

设备启停约束第一版只做“是否运行”的状态约束，不先做最小启停时间、爬坡约束和启停成本。这样既满足 MILP，又不会让第一版过度复杂。

## 4. 数据方案

第一版使用典型 24 小时模拟数据。

输入数据包括：

1. `wind_available`：风电可发功率。
2. `pv_available`：光伏可发功率。
3. `electric_load`：电负荷。
4. `heat_load`：热负荷。
5. `hydrogen_load`：氢负荷。
6. `grid_price`：分时电价。
7. 设备参数：容量、功率上限、效率、COP、初始状态。
8. 经济参数：天然气价格、碳价、弃电惩罚、运维成本。
9. 排放参数：电网排放因子、天然气排放因子。

典型数据生成逻辑：

1. 光伏：白天单峰，夜间为 0。
2. 风电：全天波动，夜间略高，加入可复现随机扰动。
3. 电负荷：白天高、夜间低，早晚有波动。
4. 热负荷：早晚较高，白天保持基础需求。
5. 氢负荷：白天有需求峰值，夜间较低。
6. 电价：峰、平、谷分时电价。

这样后面你看代码时，可以按“数据 -> 模型 -> 求解 -> 场景 -> 输出”的顺序理解。

## 6. 代码风格约定

第一版代码以“清晰可学”为优先级，不追求过度抽象。

约定如下：

1. 文件名、变量名、函数名使用英文。
2. 中文注释解释每个关键变量、约束和函数用途。
3. 对核心模型代码尽量写逐行中文注释。
4. 不写过于复杂的 Python 技巧，优先使用直观写法。
5. 每个模型文件只写一类约束，避免一个文件几百行看不清。
6. 图表标题、坐标轴和 README 说明使用中文。
7. 单位在参数名、注释或配置表中写清楚。

示例风格：

```python
# 创建电池充电功率变量，单位为 kW
model.p_battery_charge = Var(model.T, domain=NonNegativeReals)

# 创建电池放电状态变量，1 表示正在放电，0 表示不放电
model.is_battery_discharging = Var(model.T, domain=Binary)
```

## 7. 场景设计

第一版场景按从简单到完整推进。

| 场景 | 名称 | 目标 |
|---|---|---|
| S0 | 传统供能 | 只用电网购电和燃气锅炉，作为基准 |
| S1 | 新能源接入 | 加入风电和光伏，看购电量与弃电 |
| S2 | 新能源 + 电池 | 加入电储能，看削峰填谷和消纳改善 |
| S3 | 新能源 + 电池 + 制氢 | 加入电解槽、储氢罐和氢负荷 |
| S4 | 加入燃料电池 | 加入氢转电路径，形成电-氢耦合闭环 |
| S5 | 低碳调度 | 加入碳价，分析成本和排放变化 |

第一轮只要求 S0 和 S1 跑通。后续按计划逐步加 S2-S5。

### Plan C：最小 MILP 模型

再完成：

1. 建立 Pyomo MILP 模型骨架。

再完成：

完成标准：

1. 电池不会同一时刻充电和放电。
2. SOC 始终在上下限范围内。
3. S2 结果可以和 S1 对比。

### Plan E：制氢和储氢

再完成：

1. 加入电解槽。
2. 加入储氢罐。
