# 06 代码结构与核心模块

> 当前核心源码与正式结果绑定提交一致。所有正式结果引用 `run_id=formal-2024-20260809T131238Z`；本章同时标出仍保留但不属于当前结论的历史路径。

## 1. 目录结构

```text
src/zero_carbon_park/
├─ config.py                 清单、配置、哈希、Git校验
├─ formal_study.py           当前正式流程总编排
├─ cli.py                    正式清单验证入口 + 旧流程兼容入口
├─ data/                     数据来源、ERA5、负荷、正式工作簿
├─ typical_days/             代表日聚类、诊断、导出
├─ planning/                 当前容量规划MILP
├─ replay/                   固定容量全年滚动回放
├─ reliability/              确定性事件与指标
├─ reporting/                指标、图表、报告、导出
├─ optimization/             HiGHS求解安全 + 旧24h模型builder
├─ models/                   旧24h场景模型组件
├─ scenarios/                旧S0—S5场景
└─ uncertainty/              旧工作簿随机/鲁棒实验
```

## 2. 当前正式主链模块

### `config.py`

- `SolverConfig`：求解器名称、时限、MIP gap。
- `CapacityBounds`：八类设备容量上界。
- `LoadReconstructionConfig`：合成负荷规模和形状。
- `StudyConfig`：全局研究配置。
- `ManifestInput`、`VerifiedRunManifest`：清单对象。
- `sha256_file()`：输入哈希。
- `build_run_manifest()`：创建新 run_id 和不可变运行目录。
- `load_verified_manifest()`：验证输入、路径、哈希、提交和状态。

面试重点：为什么正式入口不能扫描根目录 Excel；为什么 Git 提交和哈希都要锁定；为什么 latest 只能在完成后更新。

### `formal_study.py`

- `FormalStudyRunConfig`：代表日、规划、回放参数。
- `run_formal_study()`：正式总入口。
- `formal_planning_cost_params()`：把默认成本参数转换为本次正式成本配置。
- `fixed_solution_sensitivity()`：固定解 OAT。
- `_canonical_reliability_starts()`：四类压力起点。
- `_reliability_events()`：18 个事件目录。
- `_atomic_write_json()`：原子写 JSON。

这是回答“从哪个函数开始读项目”的首选文件。

### `data/annual_pipeline.py`

- `AnnualWeatherConfig`、`CDSCredentials`：气象配置和凭据对象。
- `preflight_cds_access()`：在下载和写文件前检查 CDS 凭据。
- `required_utc_window()`：计算覆盖本地 2024 全年的 UTC 区间。
- `transform_era5_hourly()`：时区、温度、辐照、风速和风光 CF。
- `wind_capacity_factor()`：风机分段功率曲线。
- `validate_annual_weather()`：8,784 小时质量门槛。
- `download_era5_hourly()`：按月/块下载并原子合并。
- `fetch_nasa_power_monthly_check()`、`compare_nasa_power_monthly()`：独立月度交叉校核。
- `_pvlib_capacity_factor()`：光伏物理链。

### `data/generator.py`

- `generate_annual_loads()`：生成电、热、氢负荷。
- `_validated_weather()`：检查天气输入。
- `_calibrate_additive_components()`：用目标平均和峰值反解形状缩放。

### `data/formal_inputs.py`

- `build_annual_model_workbook()`：把天气、负荷、价格和参数组装为模型输入对象。
- `build_representative_workbooks()`：把代表日小时表构造成规划工作簿。
- `capacity_upper_bounds_kw()`：输出容量上界。

### `data/sources.py`

- `SourceRecord`、`AssumptionRecord`：来源和假设的数据结构。
- `SourceRegistry`：按字段和时间选择唯一有效主来源。
- `load_source_registry()`、`load_assumptions()`：读取元数据。
- `validate_assumptions()`、`_validate_primary_intervals()`：禁止冲突主来源和伪装成测量值的假设。

### `typical_days/`

- `RepresentativePeriodConfig`、`RepresentativePeriodResult`：聚类配置/结果。
- `build_representative_periods()`：主入口。
- `_daily_feature_matrix()`：构造标准化日向量。
- `_identify_extreme_days()`：强制极端日。
- `_fit_k_medoids()`：聚类。
- `_build_chronology()`：日映射、转移统计和链接文件。
- `reconstruct_hourly()`、`evaluate_compression()`、`validate_compression()`：压缩误差。
- `write_representative_period_artifacts()`：写出代表期证据。

关键代码事实：`_build_chronology()` 的产物没有被当前规划约束消费。

### `planning/`

- `PlanningCostParams`、`GridTariff`、`capital_recovery_factor()`：成本和电价。
- `build_capacity_planning_model()`：模型装配。
- `add_capacity_variables()`、`add_operation_variables()`：变量。
- `add_planning_constraints()`：所有正式物理/工程约束；重要内部规则有 `power_balance_rule`、`battery_soc_rule`、`h2_storage_rule`。
- `add_capacity_planning_objective()`：成本、年化投资、低碳上限和目标。
- `solve_engineering_portfolios()`：三类方案顺序求解。
- `_require_full_load_service()`：经济/低碳规划固定电失供为 0。
- `extract_capacity_planning_results()`：容量、小时、汇总、约束表。
- `_clean_nonnegative()`：清理容差内负数。

### `optimization/solver.py`

- `solve_model()`：设置 `appsi_highs`、时限和 gap；处理 optimal、feasible、time limit、incumbent 与 actual gap。

注意：[`optimization/builder.py`](../src/zero_carbon_park/optimization/builder.py) 是旧 24 小时模型入口；当前容量规划使用 `planning/builder.py`。

### `replay/`

- `ReplayConfig`：年份、前视、提交、求解器、初末状态。
- `run_rolling_replay()`：53 窗口滚动回放。
- `ReplayState`：跨窗传递电池和氢状态。
- `evaluate_replay_quality()`：小时覆盖、ENS、平衡残差、正式时间轴。

### `reliability/`

- `ReliabilityEvent`：起点、时长、孤网、故障设备。
- `select_stress_start_times()`：从全年表选压力起点。
- `build_outage_event_catalog()`：通用事件目录构造；正式流程还用 `formal_study._reliability_events()` 固定目录。
- `run_reliability_event()`：单事件。
- `run_reliability_catalog()`：批量事件。
- `compute_deterministic_reliability_metrics()`：ENS、供给率、连续失供、生存时间。
- `validate_nested_event_results()`：检查不同持续时间结果的嵌套合理性。

### `reporting/`

- `add_hourly_carbon_metrics()`：位置法和零碳园区口径逐时碳排。
- `build_engineering_comparison()`：把规划成本、回放运行和可靠性聚合到一个方案表。
- `generate_static_engineering_outputs()`（位于 `engineering_report.py`）：生成正式图表、技术报告和结果索引。
- `plots.py`：年度持续曲线、代表日误差、容量成本、月度碳、状态、极端周、可靠性、权衡、敏感性图。

图表函数要求明确 `source_note`，目的是让图本身带数据来源提示。

## 3. 正式脚本

| 文件 | 作用 | 是否当前正式结论入口 |
|---|---|---|
| `scripts/run_formal_study.py` | 用 manifest 调用正式总流程 | 是 |
| `scripts/build_codex_data_workbook.py` | 从明确的 processed CSV 生成审计工作簿，限制输入/输出目录 | 辅助 |
| `scripts/build_annual_data_workbook.mjs` | 工作簿构建 | 辅助 |
| `scripts/run_new_source_models.py` | 旧“新数据包”兼容/实验编排 | 否 |
| `scripts/generate_result_doc.py` | 从旧分析汇总生成结果文档 | 否 |

## 4. 历史兼容代码边界

下列代码仍能帮助理解演进，但不能为当前结果提供数字：

- `models/` + `optimization/builder.py`：旧 24 小时调度模型；
- `scenarios/`：旧 S0—S5；
- `typical_days/get_default_typical_days()`：旧的三种手工典型日；
- `planning/pareto.py`、`planning/sensitivity.py`：旧工作簿上的重新优化实验；
- `uncertainty/`：旧随机/鲁棒/压力测试研究；
- `cli.py --workbook`：明确打印 `legacy_input_mode`。

正式 `--manifest` 模式甚至会拒绝同时请求这些 legacy actions。

## 5. 测试结构

`tests/` 覆盖：

- 数据与时轴：`test_annual_data_pipeline.py`、`test_load_reconstruction.py`、`test_source_registry.py`；
- 代表日：`test_representative_periods.py`、`test_typical_day_generation.py`；
- 规划与物理：`test_capacity_planning.py`、`test_planning_physics.py`、`test_engineering_portfolios.py`；
- 求解安全：`test_solver_safety.py`；
- 回放：`test_full_year_replay.py`；
- 可靠性：`test_reliability_events.py`、`test_reliability_metrics.py`；
- 清单：`test_run_manifest.py`；
- 报告和指标：`test_engineering_comparison.py`、`test_plot_empty_series.py`；
- 旧模型回归：S0—S5、随机/鲁棒、旧敏感性等测试。

测试通过只能说明实现行为符合断言；正式结论还必须检查产物 CSV 和运行清单。

## 6. 推荐阅读顺序

1. `formal_study.py::run_formal_study()` 看主流程。
2. `planning/runner.py::solve_engineering_portfolios()` 看三方案差异。
3. `planning/builder.py` → `variables.py` → `constraints.py` → `objective.py` 看数学模型。
4. `replay/runner.py::run_rolling_replay()` 看全年验证。
5. `reliability/runner.py` + `metrics.py` 看事件。
6. `data/annual_pipeline.py` + `generator.py` 看数据来源与合成边界。
7. `reporting/metrics.py` 看每个指标究竟怎么计算。
