## 5. 生成下一次正式运行

不要修改或复用 `formal-2024-20260809T131238Z`。下一次正式运行应按以下顺序执行：

1. 确认代码和字段级来源注册表处于目标版本；
2. 下载/更新原始数据，保存在 `data/raw/`，不得从历史结果目录反向取数；
3. 更新来源登记、适用期、原文件哈希和工程假设；
4. 生成新的 UTC 时间戳 run_id；
5. 创建绑定当前 Git 提交和全部输入 SHA256 的新 manifest；
6. 运行正式入口；
7. 检查 completion、回放质量、求解状态、事件数、图表索引；
8. 只有全部交付物完整时才更新 latest 指针和文档。

正式入口形式：

```powershell
.\engrysystem-env\Scripts\python.exe scripts\run_formal_study.py artifacts\runs\<new_run_id>\manifest.json
```

项目 CLI 也提供显式 `--manifest` 正式入口；不得同时传入旧 workbook、旧 action 或另一个 output 目录。

## 6. CDS 凭据安全

CDS API 的 URL 和 key 只写入当前用户的 CDS 配置或安全凭据存储，不写入 `.env`、Markdown、manifest、日志或 Git。报告只记录数据集、区域、变量、时间范围、下载日期和文件 SHA256，不记录密钥。

如果密钥曾出现在聊天、终端输出或仓库文件中，建议在 CDS 账户侧轮换；轮换密钥不会改变已经下载并由 SHA256 固定的 ERA5 文件。

第二条命令在当前有效文档中应只命中“禁止沿用旧叙事”等历史说明，不应出现旧结果或占位数字。还应人工核对：

- 简历数字来自[结果与指标参考](结果与指标参考.md)。

## 8. 常见异常

| 异常 | 含义 | 处理 |
| --- | --- | --- |
| manifest 名称不匹配 | 目录、文件或内部 run_id 不一致 | 新建一致的 run_id，不修改历史运行 |
| Git revision drift | manifest 与当前代码版本不同 | 在独立旧版本 worktree 复现，或创建新 manifest |
| replay publication gate failed | 8,784 时轴、ENS 或平衡残差不合格 | 保留失败目录，修复后使用新 run_id |
| 低碳型 time limit | 有 incumbent 但未达到目标 gap | 报告实际 gap；必要时延长求解时间后新跑 |
| 代表日月度门失败 | 压缩不能支撑月度结论 | 保留全年回放，或改进代表期方法后新跑 |
