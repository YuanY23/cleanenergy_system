本次实验的预定数据产品均已生成：三种方案都有容量、成本、碳排、8,784 小时回放、事件级可靠性与静态图表结果。不存在“某个方案没有跑出数据”的缺口。

需要区分的是，结果存在不满足工程目标或质量门的内容，这些不是漏跑：

- 12 代表日未通过月度误差门，已由完整全年回放承担最终运行校核；
- 低碳型到达时间上限，保留 gap 1.335% 的可行解；
- 孤网事件中存在 ENS、关键负荷和氢供应缺口，说明方案有真实短板；
- 敏感性为固定方案的一次一变暴露，没有重新优化。

因此本次状态是“成果完整、边界和不足已披露”，不是“所有方案在所有指标上都完美”。

## 4. 权威优先级

当文档与结果发生冲突时，按以下顺序判断：

1. `manifest.json`、`completion.json` 和带 run_id 的原始 CSV；
2. 本目录的[结果与指标参考](结果与指标参考.md)；
3. 本目录的[项目研究报告](项目研究报告.md)与[项目介绍](项目介绍.md)；
4. 根 README 和其他导航文档；
5. 历史归档仅供追溯，不参与当前结论。

自动生成的静态技术报告用于图表配套；如果其中的格式化数值与原始 CSV 精度不同，以 CSV 为准。

## 5. AI 学习和引用规则

仓库根目录 [AGENTS.md](../../AGENTS.md) 已设置全局规则。任何 AI 在回答本项目问题前，应先读取本目录 README、`LATEST_PROJECT.json` 和本交付说明，然后按任务读取研究报告或结果参考。

AI 不得：

- 从 `archive/`、历史结果归档、根目录旧 Excel 或失败运行中抽取当前数字；
- 把合成负荷写成真实企业 SCADA；
- 把低碳型写成严格全局最优；
- 把确定性孤网压力测试写成概率可靠性或标准认证；
- 混用位置法和零碳园区核算口径；
- 保存或输出用户的 CDS API 密钥等凭据。

## 6. 正式结果的冻结关系

结果运行固定在模型提交 `34a40e7c11bad8b09c7d48c5c37d489151dfdc3b`。交付文档可以在之后单独改进，因此“当前文档 Git 提交”不等于“模型结果 Git 提交”。这不是数据不一致：manifest 记录的是产生结果时的代码版本，文档记录的是对该冻结结果的解释版本。

旧 manifest 在新的 Git HEAD 上会因版本漂移而拒绝重新运行，这是预期的防污染行为。要生成新结果，必须创建新的 run_id 和绑定当前代码的新 manifest，不能覆盖本次目录。
