## 0. 一句话讲清这个项目

这个项目构建了一个零碳园区综合能源系统优化框架，用 Python、Pyomo 和 HiGHS 建立电、热、氢、储能耦合的线性/混合整数优化模型，研究风电、光伏、电池、热泵、电解槽、储氢、燃料电池、燃气锅炉、碳价和碳约束对园区运行成本、碳排放、可再生能源消纳和设备容量配置的影响。

更适合面试的说法：

> 我做的是一个零碳园区综合能源系统优化项目。项目从 Excel 数据包读取 24 小时负荷、风光出力、能源价格和设备参数，先做 S0 到 S5 六类日调度场景对比，再扩展到夏季、冬季、过渡季三类典型日年化分析，最后把设备容量作为决策变量，做容量规划、投资敏感性、成本-碳排 Pareto 分析，以及风光和负荷不确定性下的压力测试、随机规划和鲁棒规划。模型核心是电、热、氢、碳四类平衡约束，目标函数是运行成本和年化投资成本最小化。

## 1. 你应该怎样学习这个项目

### 1.1 第一层：先懂项目要解决什么问题

项目要回答的是：

1. 零碳园区中，电负荷、热负荷、氢负荷如何由多种设备协同满足。
2. 风电、光伏接入后，如何减少外购电和碳排放。
3. 电池、制氢、储氢、热泵、燃料电池分别在系统中承担什么作用。
4. 如果加入碳价或碳排放上限，系统调度策略和设备容量会怎样变化。
5. 设备投资成本变化时，最优容量配置是否稳定。
6. 风光预测偏差、负荷偏高等不确定性出现时，系统是否还能经济可行运行。

### 1.2 第二层：再懂模型抽象

项目把真实能源系统抽象为四类守恒或核算关系：

| 能流 | 核心问题 | 代码位置 |
|---|---|---|
| 电力 | 电源侧等于电负荷、热泵、电池充电、电解槽耗电 | `src/zero_carbon_park/models/constraints_power.py` |
| 热力 | 热泵供热和燃气锅炉供热共同满足热负荷 | `src/zero_carbon_park/models/constraints_heat.py` |
| 氢气 | 制氢、放氢、外部补氢满足氢负荷、充氢、售氢和燃料电池耗氢 | `src/zero_carbon_park/models/constraints_hydrogen.py` |
| 碳排放 | 外购电间接排放和燃气直接排放之和 | `src/zero_carbon_park/models/constraints_carbon.py` |

### 1.3 第三层：最后懂代码如何落地

代码主线是：

```text
Excel 数据包
  -> data.loader.load_input_workbook()
  -> InputWorkbook(timeseries, device_params, economic_params, scenarios)
  -> scenarios.runner.run_scenario()
  -> optimization.builder.build_minimal_milp_model()
  -> optimization.solver.solve_model()
  -> optimization.results.extract_minimal_results()
  -> CSV / Excel / PNG / Markdown 输出
```

容量规划主线是：

```text
Excel 数据包
  -> 生成夏季、冬季、过渡季典型日
  -> planning.builder.build_capacity_planning_model()
  -> 容量变量 + 运行变量联合优化
  -> planning.results.extract_capacity_planning_results()
  -> 年度成本、年度碳排、最优设备容量输出
```

## 4. 数据输入设计

### 4.1 `InputWorkbook`

代码位置：`src/zero_carbon_park/data/loader.py`

核心数据结构：

```python
@dataclass(frozen=True)
class InputWorkbook:
    timeseries: pd.DataFrame
    device_params: pd.DataFrame
    economic_params: pd.DataFrame
    scenarios: pd.DataFrame
```

含义：

| 字段 | 作用 |
|---|---|
| `timeseries` | 24 小时时间序列，包括风光可用功率、电/热/氢负荷、电价、气价、电网碳因子、碳价 |
| `device_params` | 设备参数，包括热泵 COP、电池容量和效率、电解槽、储氢、燃料电池、锅炉等 |
| `economic_params` | 经济参数，包括能源价格、碳价、碳排放因子、弃电惩罚、运维成本 |
| `scenarios` | 场景说明表 |

### 4.2 关键时间序列字段

| 字段 | 含义 |
|---|---|
| `hour` | 0 到 23 的小时编号 |
| `pv_cf` | 光伏容量因子 |
| `wind_cf` | 风电容量因子 |
| `pv_available_kw` | 光伏可发功率 |
| `wind_available_kw` | 风电可发功率 |
| `electric_load_kw` | 电负荷 |
| `heat_load_kw` | 热负荷 |
| `hydrogen_load_kg` | 氢负荷 |
| `electricity_price_cny_per_kwh` | 分时电价 |
| `gas_price_cny_per_m3` | 天然气价格 |
| `grid_emission_kgco2_per_kwh` | 电网购电碳排放因子 |
| `carbon_price_cny_per_tco2` | 碳价 |

### 4.3 数据校验逻辑

代码位置：`src/zero_carbon_park/data/validation.py`

校验内容：

1. 时间序列表必须包含全部必要字段。
2. 默认必须正好 24 行。
3. `hour` 必须从 0 连续到 23。
4. 必填字段不能缺失。
5. 风光、负荷、价格、碳因子等字段不能为负。
6. 参数表必须包含 `category/name_cn/parameter/unit/value` 等字段。
7. 参数值必须能转为数值。

面试回答：

> 数据校验是为了避免优化模型吃到脏数据后产生不可解释结果。比如 hour 不连续会导致 SOC 递推错位，负负荷或负电价如果不是设计场景会扭曲目标函数，参数缺失会让 Pyomo 建模阶段直接失败。所以我在数据进入模型前做字段、长度、连续性、缺失值和非负性校验。

## 5. 基础场景 S0-S5

代码位置：`src/zero_carbon_park/scenarios/definitions.py`

| 场景 | 启用设备/机制 | 研究目的 |
|---|---|---|
| S0 | 电网购电 + 燃气锅炉 | 传统供能基准 |
| S1 | S0 + 风电 + 光伏 | 看新能源接入的降本降碳效果 |
| S2 | S1 + 电池储能 | 看电池对削峰填谷和新能源消纳的作用 |
| S3 | S2 + 电解槽 + 储氢 + 氢负荷 | 看电制氢和储氢系统的影响 |
| S4 | S3 + 热泵 + 燃料电池 | 构成电-热-氢-储完整耦合 |
| S5 | S4 + 碳价 | 低碳调度场景 |

技术实现方式：

1. `get_minimal_scenario_config(scenario_id)` 返回布尔开关。
2. `optimization.builder` 把布尔开关转成 0/1 参数。
3. 不启用的设备容量或可用资源被乘以 0。
4. 同一套约束可复用，不需要为每个场景写一套模型。

这个设计的优点：

> 场景扩展很方便。新增一个场景只要新增开关配置，不需要复制建模代码，可以保证不同场景之间的比较只来自设备启用差异，而不是来自模型结构差异。

## 6. 日调度 MILP 模型

### 6.1 模型类型

基础 S0-S5 调度模型是 24 小时日调度混合整数线性规划，MILP 即 Mixed Integer Linear Programming。混合整数的原因是模型包含二进制变量，例如：

| 二进制变量 | 作用 |
|---|---|
| `is_heat_pump_on[t]` | 控制热泵是否运行 |
| `is_battery_charging[t]` | 控制电池充电状态 |
| `is_battery_discharging[t]` | 控制电池放电状态 |
| `is_electrolyzer_on[t]` | 控制电解槽是否运行 |
| `is_fuel_cell_on[t]` | 控制燃料电池是否运行 |

### 6.2 决策变量

代码位置：`src/zero_carbon_park/models/variables.py`

按能流分组：

| 类别 | 变量 |
|---|---|
| 电力 | `grid_buy`, `pv_used`, `pv_curtail`, `wind_used`, `wind_curtail` |
| 热力 | `heat_pump_power`, `heat_pump_heat`, `gas_boiler_heat`, `gas_consumption` |
| 电池 | `battery_charge`, `battery_discharge`, `battery_soc` |
| 氢能 | `electrolyzer_power`, `h2_production`, `h2_charge`, `h2_discharge`, `h2_storage`, `h2_external_supply`, `h2_sale`, `h2_fuel_cell`, `fuel_cell_power` |
| 碳排 | `carbon_emission`, `carbon_cap_excess` |

### 6.3 电力平衡

代码位置：`src/zero_carbon_park/models/constraints_power.py`

数学表达：

```text
grid_buy[t]
+ pv_used[t]
+ wind_used[t]
+ battery_discharge[t]
+ fuel_cell_power[t]
= electric_load[t]
+ heat_pump_power[t]
+ battery_charge[t]
+ electrolyzer_power[t]
```

解释：

左边是电力来源，右边是电力去向。热泵和电解槽本质是电负荷，因为它们消耗电能分别产生热和氢。

新能源可用功率约束：

```text
pv_used[t] + pv_curtail[t] = pv_available[t]
wind_used[t] + wind_curtail[t] = wind_available[t]
```

新能源消纳率：

```text
renewable_consumption_rate =
  sum(pv_used + wind_used) / sum(pv_available + wind_available)
```

### 6.4 热力平衡

代码位置：`src/zero_carbon_park/models/constraints_heat.py`

热平衡：

```text
heat_pump_heat[t] + gas_boiler_heat[t] = heat_load[t]
```

热泵转换：

```text
heat_pump_heat[t] = heat_pump_power[t] * COP
```

燃气锅炉耗气：

```text
gas_consumption[t] =
  gas_boiler_heat[t] / gas_boiler_eff / gas_lhv
```

面试追问：为什么热泵能降碳？

回答：

> 热泵用电把空气中的低品位热能搬运到热网，COP 通常大于 1，模型中用 `heat_pump_heat = heat_pump_power * COP` 表达。相比燃气锅炉，热泵减少了天然气直接燃烧排放。如果电力来自风光或低碳电网，热泵替代锅炉能显著降低园区 Scope 1 直接排放。

### 6.5 电池 SOC 约束

代码位置：`src/zero_carbon_park/models/constraints_storage.py`

SOC 递推：

```text
battery_soc[t] =
  previous_soc
  + battery_charge[t] * battery_eta_ch
  - battery_discharge[t] / battery_eta_dis
```

容量约束：

```text
battery_soc[t] <= battery_energy_max
```

充放电互斥：

```text
is_battery_charging[t] + is_battery_discharging[t] <= 1
```

功率约束：

```text
battery_charge[t] <= is_battery_charging[t] * battery_power_max
battery_discharge[t] <= is_battery_discharging[t] * battery_power_max
```

末端闭环：

```text
battery_soc[last_hour] = battery_initial_soc
```

为什么要有末端闭环：

> 如果没有末端 SOC 约束，模型可能在最后一个小时把电池完全放空，获得一个看似更低的当天成本，但这相当于透支了下一天的初始状态。末端闭环让 24 小时调度没有净借用储能，结果更公平。

### 6.6 氢系统约束

代码位置：`src/zero_carbon_park/models/constraints_hydrogen.py`

电解槽制氢：

```text
h2_production[t] = electrolyzer_power[t] / electrolyzer_kwh_per_kg
```

燃料电池发电：

```text
fuel_cell_power[t] = h2_fuel_cell[t] * fuel_cell_kwh_per_kg
```

氢平衡：

```text
h2_production[t] + h2_discharge[t] + h2_external_supply[t]
= hydrogen_load[t] + h2_charge[t] + h2_sale[t] + h2_fuel_cell[t]
```

储氢罐状态：

```text
h2_storage[t] = previous_storage + h2_charge[t] - h2_discharge[t]
h2_storage[t] <= h2_storage_capacity
```

外部补氢变量的意义：

> `h2_external_supply` 是一个可行性兜底变量。氢负荷偏高或者本地制氢能力不足时，模型可以外部补氢，但成本设得很高。这样模型不会直接 infeasible，同时结果里能暴露“本地系统供氢能力不足”的缺口。

### 6.7 碳排放约束

代码位置：`src/zero_carbon_park/models/constraints_carbon.py`

碳排放核算：

```text
carbon_emission[t] =
  grid_buy[t] * grid_emission_factor[t]
  + gas_consumption[t] * gas_emission_factor
```

碳上限约束：

```text
sum(carbon_emission[t]) <= carbon_emission_cap + carbon_cap_excess
```

`carbon_cap_excess` 的作用：

> 它是碳约束超额变量，配合高惩罚成本使用。这样当碳上限过严导致物理不可行时，模型仍然能给出一个结果，并告诉我们超出了多少，而不是直接求解失败。

### 6.8 目标函数

代码位置：`src/zero_carbon_park/models/objective.py`

目标是最小化 24 小时总运行成本：

```text
min total_cost =
  grid_buy * grid_price
+ gas_consumption * gas_price
+ curtailment * curtail_penalty
+ carbon_emission * carbon_price
+ battery_throughput * battery_om
+ h2_production * electrolyzer_om
+ h2_external_supply * h2_external_supply_cost
+ fuel_cell_power * fuel_cell_om
- h2_sale * h2_sale_price
+ carbon_cap_excess * carbon_cap_excess_penalty
```

面试回答：

> 目标函数不是单纯电费最小，而是综合运行成本最小。它同时考虑购电、燃气、弃风弃光惩罚、碳价、电池循环运维、电解槽运维、外部补氢、燃料电池运维、售氢收益和碳超额惩罚，所以能反映多能系统经济性和低碳约束之间的权衡。

## 7. 容量规划模型

### 7.1 从调度到规划的变化

日调度模型回答：

```text
设备容量已知，今天每小时怎么运行成本最低？
```

容量规划模型回答：

### 7.4 年化投资成本

代码位置：`src/zero_carbon_park/planning/cost_params.py`

使用资本回收系数 CRF，把一次性 CAPEX 转成年度成本：

```text
CRF = r * (1 + r)^N / ((1 + r)^N - 1)
```

其中：

| 符号 | 含义 |
|---|---|
| `r` | 折现率，默认 0.08 |
| `N` | 设备寿命 |

年化投资成本：

```text
annualized_capex =
  capacity * unit_capex * CRF
```

### 7.5 容量规划目标函数

代码位置：`src/zero_carbon_park/planning/objective.py`

```text
min annual_total_cost =
  annual_operation_cost
+ annualized_investment_cost
```

其中：

```text
annual_operation_cost =
  sum(weight_days[d] * daily_operation_cost[d])
```

面试回答：

> 容量规划是规划和运行一体化优化。容量变量在所有典型日中共享，表示一次性投资决策；运行变量按典型日和小时展开，表示不同季节工况下的调度策略。目标函数把典型日运行成本按代表天数年化，再加设备年化投资成本。

### 7.6 为什么容量规划里去掉了部分二进制变量

日调度中电池充放电互斥用二进制变量表达。容量规划为了降低求解复杂度，采用连续松弛。原因：

1. 容量规划有多个典型日和更多变量。
2. 如果保留大量二进制变量，模型求解规模会明显增大。
3. 电池充放电有效率损失，目标又是成本最小化，正常情况下模型不会主动选择无意义的同时充放电。

被追问时的边界回答：

> 这个松弛不是在任何情况下都完全严格。如果充放电效率为 100%、弃电惩罚为 0、或者存在退化的等价最优解，模型可能出现同时充放电的非物理解。所以如果要用于工程投产，我会补充互斥约束，或者加入很小的吞吐惩罚，或者对结果做充放电互斥检查。

### 8.2 压力测试

代码位置：`src/zero_carbon_park/uncertainty/stress_test.py`

逻辑：

1. 先跑确定性容量规划，得到基准最优容量。
2. 固定这些容量变量。
3. 对每个不确定性场景重新运行调度。
4. 比较成本、碳排、外部补氢等指标相对正常场景的变化。

关键函数：

```python
_fix_capacity_variables(model, fixed_capacity)
```

面试回答：

> 压力测试不是重新优化容量，而是检验已有容量方案在预测偏差下的承压能力。它回答的是“这个方案抗不抗风险”，不是“风险下最优方案是什么”。

### 8.3 随机容量规划

代码位置：`src/zero_carbon_park/uncertainty/stochastic_planning.py`

逻辑：

```text
3 个典型日 x 6 个不确定性场景 = 18 个加权运行场景
```

容量变量在 18 个场景中共享，运行变量按场景展开，目标最小化概率加权的期望年度成本。

权重：

```text
stochastic_weight = typical_day_weight_days * uncertainty_probability
```

面试回答：

> 随机规划的核心是期望最优。它假设场景概率可信，把高概率和低概率场景按权重放进目标函数，求一个平均意义上最经济的容量方案。

### 8.4 鲁棒容量规划

代码位置：`src/zero_carbon_park/uncertainty/robust_planning.py`

逻辑：

1. 同样生成 18 个典型日-不确定性组合。
2. 但不按概率加权。
3. 每个不确定性 case 都按 365 天意义下核算。
4. 引入辅助变量 `worst_case_total_cost`。
5. 约束它大于等于所有不确定性 case 的年度总成本。
6. 目标最小化这个最坏场景成本。

数学表达：

```text
min theta
s.t. theta >= annual_total_cost[u], for all u in U
```

面试回答：

> 鲁棒规划的核心是最坏情形最优。它牺牲一部分正常场景经济性，换取不利场景下成本上界可控，更适合对供能安全要求高、不能接受极端场景崩溃的园区。

## 12. 秋招项目讲述模板

### 12.1 30 秒版本

> 我做了一个零碳园区电-热-氢-储综合能源系统优化项目。项目用 Python、Pyomo 和 HiGHS 建立混合整数线性规划模型，统一描述风光、电网、电池、电解槽、储氢、热泵、燃气锅炉、燃料电池和碳排放成本。先比较 S0 到 S5 六类运行场景，再扩展到多典型日年化、设备容量规划、投资敏感性和成本-碳排 Pareto 分析，最后加入风光和负荷不确定性，做压力测试、随机规划和鲁棒规划。结果显示，风光、热泵、电解槽和储氢是主要降碳路径，燃料电池在当前参数下经济性不足，系统在碳排放约束收紧到基准 40% 时仍可行，但成本会上升约 1.57%。

### 12.2 2 分钟版本

> 项目背景是零碳园区同时有电负荷、热负荷和氢负荷，单一能源系统很难解释风光、电池、热泵、制氢和储氢之间的协同关系。所以我把系统抽象成电、热、氢、碳四类平衡约束。
>
> 在日调度层面，我建立了 24 小时 MILP 模型。电力平衡中，电网购电、风光、电池放电和燃料电池发电满足电负荷、热泵耗电、电池充电和电解槽耗电；热平衡中，热泵和燃气锅炉满足热负荷；氢平衡中，电解槽制氢、储氢放氢和外部补氢满足氢负荷、储氢充氢、售氢和燃料电池耗氢；碳排放由外购电间接排放和燃气直接排放组成。目标函数最小化购电、燃气、弃电惩罚、碳成本、设备运维、补氢成本，并扣除售氢收益。
>
> 在规划层面，我用夏季、冬季、过渡季三个典型日代表全年，把风电、光伏、电池、电解槽、储氢、燃料电池和热泵容量作为连续决策变量，目标函数是年运行成本加年化投资成本。年化投资成本用 CRF 资本回收系数计算。后续又做了投资敏感性、碳排上限 Pareto、压力测试、随机规划和鲁棒规划。
>
> 结果上，S0 到 S5 对比显示，风光和电池显著降低外购电和碳排，热泵替代燃气锅炉后天然气消耗降为 0。容量规划最优结果为风电约 21.9 MW、光伏约 5.8 MW、电解槽约 2.9 MW、储氢约 406 kg、热泵 3.15 MW，燃料电池为 0，说明当前参数下燃料电池常规回发电不经济。Pareto 分析显示碳排上限收紧到基准 40% 时仍可行，减排 60% 对应成本增幅约 1.57%。

### 12.3 技术亮点版本

> 技术亮点有四个。第一，模型不是单能源调度，而是电、热、氢、储、碳全耦合建模。第二，代码上把数据层、场景层、模型约束、求解器、结果提取和报告导出拆成独立模块，场景扩展不需要复制模型。第三，从确定性日调度扩展到多典型日容量规划，再扩展到投资敏感性和 Pareto 分析，能回答工程规划中的经济性和低碳权衡问题。第四，加入了压力测试、随机规划和鲁棒规划，能分析风光与负荷预测误差带来的容量风险。

## 13. 高频面试问答

### Q1：为什么这是 MILP？

回答：

> 因为模型既有连续变量，也有二进制变量。连续变量包括购电功率、风光利用、储能 SOC、制氢量、储氢量和碳排放；二进制变量用于设备启停和电池充放电互斥，比如 `is_battery_charging + is_battery_discharging <= 1`。目标函数和约束都是线性的，所以是混合整数线性规划。

### Q2：电、热、氢之间是怎么耦合的？

回答：

> 电和热通过热泵耦合，热泵消耗电能供热；电和氢通过电解槽耦合，电解槽消耗电能制氢；氢和电通过燃料电池耦合，燃料电池消耗氢气发电；电池和储氢分别承担电能和氢能的时移。这样风光电既可以直接供电，也可以用于制氢或供热，实现多能协同。

### Q3：为什么燃料电池容量规划结果是 0？

回答：

> 在当前参数下，燃料电池的常规回发电经济性不足。它需要先用电解槽制氢，再通过燃料电池发电，中间有能量转换损失，还要承担设备投资和运维成本。如果模型没有加入备用容量价值、停电损失、峰时电价套利或辅助服务收益，燃料电池就很难在成本最小目标下被选择。所以结果为 0 并不表示燃料电池没有工程价值，而是说明当前收益机制没有覆盖它的韧性价值。

### Q4：为什么容量规划里电池容量比调度场景给定容量小？

回答：

> 调度场景使用的是给定设备参数，不考虑电池新增投资成本。容量规划把电池功率和容量作为投资变量，并把年化投资成本放入目标函数。考虑 CAPEX 后，模型只保留经济上必要的电池容量，用于有限的日内平衡，因此最优容量会比固定容量调度中可用的电池规模小。

### Q5：为什么 S5 加碳价后碳排没有比 S4 下降？

回答：

> S5 的碳价确实增加了碳成本，但当前碳价水平不足以改变 S4 的最优调度结构。S4 已经通过热泵把燃气消耗降到 0，主要碳排来自外购电。如果继续减排需要进一步改变风光、电池或制氢调度，但在当前设备容量和电价结构下，这些调整的边际成本高于碳价带来的收益，所以调度结构不变。

### Q6：为什么要做 Pareto 分析？

回答：

> 单一成本最小只能得到一个点，不能告诉业主“更低碳要多花多少钱”。Pareto 分析用碳排放上限作为约束，多次求解容量规划模型，得到不同减排目标下的最低成本。这样可以量化减排 10%、20%、直到 60% 的成本增幅，为低碳目标和投资预算之间的权衡提供依据。

### Q7：随机规划和鲁棒规划有什么区别？

回答：

> 随机规划追求期望成本最优，适合场景概率可信、业主更关注长期平均经济性的情况。鲁棒规划追求最坏场景成本最小，适合供能安全要求高、不能接受极端场景失效的情况。随机规划结果通常更经济，鲁棒规划结果通常更保守、投资更高。

### Q8：压力测试和随机规划有什么区别？

回答：

> 压力测试是先固定一个基准容量方案，再看它在不同扰动下表现如何，不重新优化容量；随机规划是在多个扰动场景下共同优化容量，容量决策一开始就考虑了不确定性。前者是评估现有方案抗风险能力，后者是设计更适应风险的方案。

### Q9：为什么用典型日而不是 8760 小时全年数据？

回答：

> 典型日能显著降低模型规模，适合研究阶段快速验证方法和比较场景。项目用夏季、冬季、过渡季三个典型日代表全年，并按代表天数加权年化。局限是它不能完全反映连续天气过程、跨日储能和极端长周期低风低光。后续如果用于真实工程，应接入 8760 小时数据或通过聚类生成更多典型日。

### Q10：模型有哪些局限？

回答：

> 第一，典型日由基准日缩放生成，还不是基于真实全年数据聚类。第二，设备投资成本是工程假设，缺少真实报价校准。第三，热泵 COP、电解槽效率、燃料电池效率都被简化为常数，没有建模部分负荷效率。第四，容量规划中部分二进制启停被连续松弛。第五，燃料电池备用价值、停电损失和辅助服务收益还没有加入。第六，电网交互只考虑购电，没有考虑上网售电、需量电费和配网约束。

### Q11：如果让你继续优化这个项目，你会做什么？

回答：

> 我会优先做四件事。第一，接入真实 8760 小时数据，或用聚类方法生成更多典型日。第二，用真实设备报价和寿命参数校准 CAPEX。第三，引入更精细的设备模型，比如热泵 COP 随温度变化、电解槽部分负荷效率、储能退化成本。第四，把燃料电池的备用容量价值和停电损失放进目标函数或约束，让模型能评价它的韧性价值，而不只是常规套利价值。

### Q12：怎么证明模型结果可信？

回答：

> 我从三方面保证可信。第一，物理约束上，电、热、氢平衡残差在测试中接近 0，SOC 和储氢都满足容量边界。第二，结果趋势符合工程直觉，比如风光降低外购电，热泵降低燃气消耗，碳约束收紧导致成本上升。第三，自动化测试覆盖数据读取、场景求解、年化权重、容量规划、敏感性、随机和鲁棒分析，能防止模型扩展时破坏已有逻辑。

## 17. 常见追问的短答

| 追问 | 短答 |
|---|---|
| 为什么不用深度学习？ | 这是优化决策问题，核心是满足物理约束下的成本最小化。深度学习可用于预测风光和负荷，但调度决策更适合数学规划。 |
| 为什么不是非线性规划？ | 当前设备效率用常数或已知参数表示，约束和目标保持线性，便于快速求解和解释。更精细设备效率曲线可用分段线性化扩展。 |
| HiGHS 和 Gurobi 有什么区别？ | HiGHS 开源，足够支持本项目 LP/MILP。Gurobi 商业求解器性能更强，适合更大规模或更复杂整数模型。 |
| 碳排怎么核算？ | 外购电乘以小时级电网排放因子，加上天然气消耗乘以燃气排放因子。 |
| 为什么新能源消纳率不是简单平均？ | 年化消纳率应该用全年新能源利用量除以全年新能源可用量，不能简单平均各典型日百分比。 |
| 为什么风电容量比光伏大？ | 当前资源曲线、负荷结构、投资成本和碳约束共同决定，结果显示风电在该参数下更有经济性。 |
| 为什么极端场景成本高？ | 风光偏低和负荷偏高导致外购电增加，碳排也随购电上升，系统运行成本和碳成本同时增加。 |
| 怎么防止模型过拟合数据？ | 用多典型日、敏感性分析、不确定性场景和鲁棒规划检查参数变化下的稳定性。 |

## 18. 你需要真正背下来的公式

电力平衡：

```text
P_grid + P_pv + P_wind + P_bat_dis + P_fc
= P_load + P_hp + P_bat_ch + P_el
```

热平衡：

```text
Q_hp + Q_gb = Q_heat_load
Q_hp = P_hp * COP
V_gas = Q_gb / eta_gb / LHV_gas
```

氢平衡：

```text
m_h2_prod + m_h2_dis + m_h2_ext
= m_h2_load + m_h2_ch + m_h2_sale + m_h2_fc
```

电池 SOC：

```text
SOC_t = SOC_{t-1} + P_ch * eta_ch - P_dis / eta_dis
```

储氢：

```text
H2_t = H2_{t-1} + H2_ch - H2_dis
```

碳排：

```text
Carbon_t = P_grid_t * EF_grid_t + V_gas_t * EF_gas
```

CRF：

```text
CRF = r(1+r)^N / ((1+r)^N - 1)
```

容量规划目标：

```text
min annual_operation_cost + annualized_investment_cost
```

随机规划目标：

```text
min CAPEX_annual + sum_s probability_s * OPEX_s
```

鲁棒规划：

```text
min theta
s.t. theta >= total_cost_u, for all uncertainty case u
```

## 19. 最后总结

这个项目的主线可以概括为：

```text
确定性日调度
  -> 多场景对比
  -> 多典型日年化
  -> 容量规划
  -> 投资敏感性
  -> 成本-碳排 Pareto
  -> 压力测试
  -> 随机规划
  -> 鲁棒规划
```

秋招中你要重点展示的不是“我会跑 Pyomo”，而是：

1. 你理解综合能源系统的电-热-氢耦合。
2. 你能把物理系统抽象成优化变量、约束和目标函数。
3. 你能解释每个设备为什么进模型，以及结果为什么合理。
4. 你能用实验数据支撑结论，而不是泛泛而谈。
5. 你知道模型局限，并能提出下一步工程化改进。

如果面试官只给你一分钟，就讲 S0-S5、容量规划和 Pareto 结论。如果面试官深入追问，就展开电力平衡、SOC、氢平衡、CRF、随机规划和鲁棒规划。只要这几条主线讲清楚，这个项目就能从“课程项目”变成“有工程建模深度的清洁能源优化项目”。
