## 0. v0.4 一句话讲清项目

这个项目用 Python、Pyomo 和 HiGHS 构建了一个零碳园区电-热-氢-储综合能源系统优化模型，从 Excel 数据包读取电负荷、热负荷、氢负荷、风光出力、价格和设备参数，先做 S0-S5 固定容量日调度，再做多典型日容量规划，并进一步加入投资成本、不确定性、随机规划、鲁棒规划、设备时变效率、燃料电池备用价值和电力市场机制，用于研究园区在经济性、低碳性、可靠性和市场收益之间的最优权衡。

面试里的高质量表述：

> 我做的是零碳园区电-热-氢-储综合能源系统优化项目。项目把风电、光伏、电网、电池、热泵、燃气锅炉、电解槽、储氢、燃料电池和碳排放统一建模。日调度层面用 MILP 描述 24 小时设备运行；容量规划层面把风电、光伏、电池、电解槽、储氢、燃料电池和热泵容量作为决策变量，目标是年度运行成本、年化投资成本、需量电费和市场收益综合最优。v0.4 进一步细化了热泵 COP、电解槽效率、燃料电池效率、电池退化、燃料电池备用价值、可再生能源上网售电和需量电费，使模型从单纯成本优化扩展为“经济性 + 低碳性 + 可靠性 + 市场机制”的综合规划模型。

含义：

| 参数 | 含义 |
|---|---|

### 4.3 数据校验

代码位置：

```text
src/zero_carbon_park/data/validation.py
```

校验逻辑：

1. 时间序列必须包含必要字段。
2. 默认必须正好 24 行。
3. `hour` 必须从 0 连续到 23。
4. 必填列不能有缺失。
5. 风光、负荷、价格、碳因子不能为负。
6. 参数表必须有 `category/name_cn/parameter/unit/value` 等字段。
7. 参数值必须能转成数值。

面试回答：

> 我先把 Excel 数据标准化成 `InputWorkbook`，再进入 Pyomo 建模。这样模型层不依赖 Excel 的中文表头，后续如果换数据源，只要保持标准字段一致，模型代码就不用改。数据校验能避免脏数据进入优化模型，例如小时不连续会导致 SOC 递推错位，负负荷或缺失参数会导致结果没有物理意义。

### 5.3 为什么日调度模型是 MILP

MILP 是 Mixed Integer Linear Programming，混合整数线性规划。

项目里有两类变量：

| 变量类型 | 示例 |
|---|---|
| 连续变量 | `grid_buy[t]`、`battery_soc[t]`、`h2_storage[t]`、`carbon_emission[t]` |
| 二进制变量 | `is_battery_charging[t]`、`is_battery_discharging[t]`、`is_heat_pump_on[t]`、`is_electrolyzer_on[t]` |

为什么需要二进制变量：

```python
model.is_battery_charging = Var(model.T, domain=Binary)
model.is_battery_discharging = Var(model.T, domain=Binary)
```

它们用于表达：

```text
同一小时电池不能同时充电和放电
设备没开机时功率必须为 0
```

面试回答：

> 这个项目的日调度模型是 MILP，因为设备出力、负荷、SOC、制氢量是连续变量，但设备启停和电池充放电互斥需要二进制变量。目标函数和约束本身保持线性，所以适合用 Pyomo 建模、HiGHS 求解。

风光可用量：

```text
pv_used[t] + pv_curtail[t] = pv_available[t]
wind_used[t] + wind_curtail[t] = wind_available[t]
```

电力平衡：

```text
grid_buy[t]
+ pv_used[t]
+ wind_used[t]
+ battery_discharge[t]
+ fuel_cell_power[t]
= electric_load[t]
+ heat_pump_power[t]
+ battery_charge[t]
+ electrolyzer_power[t]
```

解释：

| 左边 | 含义 |
|---|---|
| `grid_buy` | 从电网买电 |
| `pv_used` | 光伏被园区直接使用 |
| `wind_used` | 风电被园区直接使用 |
| `battery_discharge` | 电池放电 |
| `fuel_cell_power` | 燃料电池发电 |

| 右边 | 含义 |
|---|---|
| `electric_load` | 园区基础电负荷 |
| `heat_pump_power` | 热泵耗电 |
| `battery_charge` | 电池充电 |
| `electrolyzer_power` | 电解槽制氢耗电 |

面试回答：

> 电力平衡体现了电源侧和负荷侧每小时必须相等。热泵和电解槽虽然产出的是热和氢，但它们输入是电，所以在电力平衡中属于用电侧；燃料电池消耗氢发电，所以属于电源侧。

### 6.2 热力侧

代码位置：

```text
src/zero_carbon_park/models/constraints_heat.py
```

热泵转换：

```text
heat_pump_heat[t] = heat_pump_power[t] * heat_pump_cop
```

燃气锅炉耗气：

```text
gas_consumption[t] = gas_boiler_heat[t] / gas_boiler_eff / gas_lhv
```

热平衡：

```text
heat_pump_heat[t] + gas_boiler_heat[t] = heat_load[t]
```

为什么热泵重要：

> 热泵的 COP 大于 1，同样供热量下，它消耗的电能小于直接电加热。如果电力由风光或低碳电网供应，热泵可以替代燃气锅炉，减少天然气燃烧和直接碳排。

### 6.3 电池储能

代码位置：

```text
src/zero_carbon_park/models/constraints_storage.py
```

充放电功率限制：

```text
battery_charge[t] <= is_battery_charging[t] * battery_power_max
battery_discharge[t] <= is_battery_discharging[t] * battery_power_max
```

充放电互斥：

```text
is_battery_charging[t] + is_battery_discharging[t] <= 1
```

SOC 递推：

```text
battery_soc[t]
= previous_soc
+ battery_charge[t] * battery_eta_ch
- battery_discharge[t] / battery_eta_dis
```

末端闭环：

```text
battery_soc[last_hour] = battery_initial_soc
```

为什么末端闭环：

> 如果没有末端 SOC 约束，模型可能在最后一小时把电池完全放空，使当天成本看起来更低，但这相当于透支了下一天。末端闭环保证 24 小时调度不借用未来储能。

### 6.4 氢能系统

代码位置：

```text
src/zero_carbon_park/models/constraints_hydrogen.py
```

制氢：

```text
h2_production[t] = electrolyzer_power[t] / electrolyzer_kwh_per_kg
```

燃料电池：

```text
fuel_cell_power[t] = h2_fuel_cell[t] * fuel_cell_kwh_per_kg
```

氢平衡：

```text
h2_production[t] + h2_discharge[t] + h2_external_supply[t]
= hydrogen_load[t] + h2_charge[t] + h2_sale[t] + h2_fuel_cell[t]
```

储氢：

```text
h2_storage[t] = previous_storage + h2_charge[t] - h2_discharge[t]
h2_storage[t] <= h2_storage_capacity
```

`h2_external_supply` 的意义：

> 外部补氢是可行性兜底。氢负荷过高或者本地制氢能力不足时，模型可以用高成本外部补氢保持可行，同时结果里会暴露供氢缺口。

### 6.5 碳排放

代码位置：

```text
src/zero_carbon_park/models/constraints_carbon.py
```

碳排放：

```text
carbon_emission[t]
= grid_buy[t] * grid_emission_factor[t]
+ gas_consumption[t] * gas_emission_factor
```

碳上限：

```text
sum(carbon_emission[t]) <= carbon_emission_cap + carbon_cap_excess
```

`carbon_cap_excess` 的意义：

> 如果碳约束过紧，模型不直接 infeasible，而是通过高惩罚的超额变量记录缺口。这可以告诉我们“差多少才能满足碳约束”。

## 8. 多典型日和年化分析

### 8.1 为什么需要典型日

单日调度只能说明某一天怎么运行，不能代表全年。全年 8760 小时直接优化会更准确，但模型更大、数据要求更高。当前项目用三个典型日近似全年：

代码位置：

```text
src/zero_carbon_park/typical_days/definitions.py
```

| 典型日 | 权重 | 作用 |
|---|---:|---|
| `TD_SUMMER` | 120 天 | 夏季，高光伏、高电负荷、低热负荷 |
| `TD_WINTER` | 120 天 | 冬季，低光伏、高风电、高热负荷 |
| `TD_TRANSITION` | 125 天 | 过渡季，接近基准 |

总权重：

```text
120 + 120 + 125 = 365
```

### 8.2 典型日生成

代码位置：

```text
src/zero_carbon_park/typical_days/generator.py
```

`generate_typical_day_workbook()` 会复制原始 `InputWorkbook`，然后按典型日配置缩放：

| 缩放对象 | 示例 |
|---|---|
| 光伏 | 夏季放大，冬季降低 |
| 风电 | 冬季放大，夏季降低 |
| 电负荷 | 夏季提高 |
| 热负荷 | 冬季提高 |
| 氢负荷 | 当前默认不变 |
| 电价、气价、碳价 | 可按季节缩放 |

### 8.3 年化逻辑

多典型日年化的核心思想：

```text
年度指标 = sum(典型日指标 * 代表天数)
```

例如：

```text
annual_grid_purchase_kwh =
  TD_SUMMER_grid_purchase * 120
+ TD_WINTER_grid_purchase * 120
+ TD_TRANSITION_grid_purchase * 125
```

面试回答：

> 典型日年化不是简单平均，而是按代表天数加权。比如夏季、冬季、过渡季分别代表 120、120、125 天，所以年度外购电、碳排、成本都要乘以对应权重后求和。

## 10. v0.4 设备运行细化怎么理解

### 10.1 热泵 COP 从常数变成可选时变参数

旧模型：

```text
heat_pump_heat[d,t] = heat_pump_power[d,t] * heat_pump_COP
```

v0.4：

```text
heat_pump_heat[d,t] = heat_pump_power[d,t] * heat_pump_cop[d,t]
```

如果 `timeseries` 中没有 `heat_pump_cop` 列，就使用设备参数中的 `heat_pump_COP`。

结果解释：

| 变化 | 影响 |
|---|---|
| COP 下降 | 同样热负荷需要更多电 |
| 热泵耗电上升 | 外购电、风光容量、电池容量可能上升 |
| 冬季热负荷高且 COP 低 | 供热侧对系统成本和容量的压力变大 |

面试回答：

> 热泵 COP 受环境温度影响，冬季低温时 COP 往往下降。v0.4 支持逐小时 COP，是为了让同样热负荷在不同季节对应不同电力需求，从而更真实地反映热泵对电力系统的压力。

### 10.2 电解槽和燃料电池效率可变

电解槽：

```text
h2_production[d,t] = electrolyzer_power[d,t] / electrolyzer_kwh_per_kg[d,t]
```

燃料电池：

```text
fuel_cell_power[d,t] = h2_fuel_cell[d,t] * fuel_cell_kwh_per_kg[d,t]
```

解释：

| 参数 | 越大意味着 |
|---|---|
| `electrolyzer_kwh_per_kg` | 制 1 kg 氢需要更多电，电解槽效率更低 |
| `fuel_cell_kwh_per_kg` | 1 kg 氢能发更多电，燃料电池效率更高 |

结果影响：

| 变化 | 模型倾向 |
|---|---|
| 电解槽耗电升高 | 制氢减少，外部补氢或储氢压力上升 |
| 燃料电池发电效率升高 | 燃料电池运行价值上升 |
| 氢链路整体效率降低 | 电制氢再发电更不经济 |

### 10.3 电池退化成本

新增参数：

```python
battery_degradation_cost_cny_per_kwh
```

进入目标函数：

```text
(battery_charge[d,t] + battery_discharge[d,t])
* battery_degradation_cost_cny_per_kwh
```

为什么要加：

> 电池循环不是免费的。即使没有显式换电池，频繁充放电也会造成寿命折损。加入退化成本后，模型不会为了很小的电价差频繁充放电。

结果解释：

| 退化成本变化 | 结果趋势 |
|---|---|
| 退化成本升高 | 电池充放电次数下降 |
| 退化成本升高 | 电池容量可能下降 |
| 退化成本升高 | 峰谷套利变弱，可能更多依赖电网或氢能 |

## 11. v0.4 燃料电池备用价值

### 11.1 为什么燃料电池常规规划可能是 0

在普通容量规划里，燃料电池要经历：

```text
电力 -> 电解槽 -> 氢气 -> 燃料电池 -> 电力
```

这条链路有三类劣势：

1. 有能量转换损失。
2. 需要电解槽、储氢、燃料电池多类投资。
3. 日常运行小时数可能不高。

所以如果目标函数只考虑日常运行成本和投资成本，燃料电池容易被判定为不经济。

### 11.2 v0.4 如何表达备用价值

新增变量：

```python
fuel_cell_backup_capacity_kw
```

约束：

```text
fuel_cell_backup_capacity_kw <= fuel_cell_power_capacity_kw
fuel_cell_backup_capacity_kw <= fuel_cell_backup_reserve_kw
fuel_cell_power_capacity_kw >= fuel_cell_backup_required_kw
```

收益：

```text
annual_fuel_cell_backup_value
= fuel_cell_backup_capacity_kw
* fuel_cell_backup_value_cny_per_kw_year
```

目标函数中扣减：

```text
annual_total_cost = ... - annual_fuel_cell_backup_value
```

### 11.3 结果应该怎么解释

| 情况 | 解释 |
|---|---|
| 备用价值为 0 | 燃料电池只靠日常发电收益参与竞争 |
| 备用价值提高 | 燃料电池容量更可能被选择 |
| 备用需求提高 | 燃料电池容量可能上升 |
| 备用价值不足以覆盖年化成本 | 燃料电池仍可能不被选择 |

面试回答：

> 燃料电池在这个项目中不应该只被看成一个普通发电机。它还有长时备用和关键负荷保障价值。v0.4 把备用容量价值显式加入目标函数，能解释为什么燃料电池即使日常发电不多，也可能因为可靠性价值被配置。

## 12. v0.4 电力市场机制

### 12.1 上网售电

新增变量：

```python
grid_sell[d,t]
pv_sold[d,t]
wind_sold[d,t]
```

可再生能源分配变为：

```text
pv_used[d,t] + pv_sold[d,t] + pv_curtail[d,t]
= pv_capacity_kw * pv_cf[d,t]

wind_used[d,t] + wind_sold[d,t] + wind_curtail[d,t]
= wind_capacity_kw * wind_cf[d,t]
```

上网定义：

```text
grid_sell[d,t] = pv_sold[d,t] + wind_sold[d,t]
```

上网限制：

```text
grid_sell[d,t] <= grid_export_limit_kw
```

售电收益：

```text
grid_sell[d,t] * grid_sell_price[d,t]
```

为什么只允许风光售电：

> 当前模型不允许“买电再卖电”，也不允许电池或燃料电池专门为上网套利。这样可以避免电价参数设置不合理时出现非工程性的套利行为。

### 12.2 需量电费

新增变量：

```python
grid_import_peak_kw
```

约束：

```text
grid_buy[d,t] <= grid_import_peak_kw
```

需量成本：

```text
annual_demand_charge_cost
= grid_import_peak_kw * demand_charge_cny_per_kw_year
```

解释：

> 需量电费不是按总电量收费，而是按最大购电功率收费。如果某一小时从电网取电特别高，全年需量费用都会增加。因此模型会更重视削峰。

结果影响：

| 参数变化 | 结果趋势 |
|---|---|
| 需量电费提高 | 电池、燃料电池、风光自用的削峰价值上升 |
| 上网电价提高 | 风光装机可能增加 |
| 上网功率限制降低 | 弃风弃光可能增加 |
| 峰值购电越高 | 需量成本越高 |

## 18. 结果变化如何解释

### 18.1 COP 变化

| COP 变化 | 影响 |
|---|---|
| COP 降低 | 热泵耗电增加 |
| 热泵耗电增加 | 电负荷侧压力增加 |
| 电负荷压力增加 | 外购电、风光、电池或氢能容量可能增加 |
| 冬季热负荷高且 COP 低 | 容量规划更偏向增加供电和削峰能力 |

一句话：

> COP 越低，同样供热需要越多电，系统电力侧压力越大。

### 18.2 电池退化成本变化

| 退化成本变化 | 影响 |
|---|---|
| 退化成本升高 | 电池充放电减少 |
| 电池使用减少 | 峰谷套利变弱 |
| 峰谷套利变弱 | 可能增加外购电或转向其他调节资源 |

一句话：

> 电池退化成本越高，模型越不愿意为小价差频繁循环电池。

### 18.3 燃料电池备用价值变化

| 备用价值变化 | 影响 |
|---|---|
| 备用价值为 0 | 燃料电池只看日常发电经济性 |
| 备用价值提高 | 燃料电池容量更可能出现 |
| 备用需求提高 | 燃料电池可能被硬性配置 |

一句话：

> 备用价值把燃料电池从“普通发电设备”提升为“可靠性资源”，因此会改变容量规划结果。

### 18.4 上网电价变化

| 上网电价变化 | 影响 |
|---|---|
| 上网电价升高 | 风光装机收益增加 |
| 上网限制较低 | 富余新能源可能被弃掉 |
| 上网电价为 0 | 模型不会因为售电而扩容风光 |

一句话：

> 上网价格越高，风光从“只满足园区自用”变成“还能创造市场收益”，装机吸引力上升。

### 18.5 需量电费变化

| 需量电费变化 | 影响 |
|---|---|
| 需量电费提高 | 最大购电功率变得更贵 |
| 最大购电功率变贵 | 电池、燃料电池、风光自用削峰价值上升 |
| 削峰价值上升 | 容量规划可能增加调节设备 |

一句话：

> 需量电费不是惩罚用多少电，而是惩罚最高从电网拿多少电，所以它会强化削峰设备的价值。

## 19. 高频面试问答

### Q1：这个项目的核心创新点是什么？

回答：

> 核心不是单独调一个设备，而是把电、热、氢、储能和碳排放放在同一个优化框架里。项目先做固定容量日调度，再做多典型日容量规划，进一步加入投资敏感性、Pareto、不确定性、随机规划和鲁棒规划。v0.4 又补充了设备时变效率、燃料电池备用价值和电力市场机制，所以可以同时解释经济性、低碳性、可靠性和市场收益。

### Q2：为什么用 Pyomo 和 HiGHS？

回答：

> Pyomo 适合把数学优化模型写成接近公式的 Python 代码，变量、参数、约束和目标函数都很清晰。HiGHS 是开源 LP/MILP 求解器，能满足当前模型规模，并且不依赖商业授权。项目更强调模型可解释和可复现，所以这个组合比较合适。

### Q3：日调度和容量规划有什么区别？

回答：

> 日调度是假设设备容量已知，只优化每小时怎么运行；容量规划把设备容量也作为决策变量，联合优化容量投资和典型日运行。日调度回答“怎么运行”，容量规划回答“装多少 + 怎么运行”。

### Q4：v0.4 为什么要加设备时变效率？

回答：

> 原来热泵 COP、电解槽耗电和燃料电池效率是常数，适合第一版建模，但不能反映季节和负荷率变化。v0.4 支持时变效率，比如冬季热泵 COP 下降会推高电力需求，电解槽效率下降会推高制氢成本，这让容量规划更接近真实设备运行。

### Q5：为什么燃料电池之前可能不被选择？

回答：

> 因为如果只考虑日常发电，燃料电池需要先制氢再发电，中间有转换损失，还要承担燃料电池投资和运维成本。在没有备用价值、停电损失或辅助服务收益时，它很难比直接用风光、电池或电网更经济。

### Q6：v0.4 怎么解决燃料电池价值被低估的问题？

回答：

> v0.4 新增了 `fuel_cell_backup_capacity_kw`，并在目标函数中加入 `annual_fuel_cell_backup_value`。这样燃料电池不仅通过日常发电产生价值，也可以通过关键负荷备用、长时保供等可靠性价值进入容量规划。

### Q7：电力市场机制具体加了什么？

回答：

> 主要加了两类。第一是可再生能源上网售电，风光富余时可以通过 `grid_sell` 上网并获得收益，但只能卖风光，避免买电卖电套利。第二是需量电费，用 `grid_import_peak_kw` 表示最大购电功率，最大购电越高，年度需量成本越高，因此模型会更重视削峰。

### Q8：为什么容量规划中有些互斥二进制没有保留？

回答：

> 容量规划同时展开多个典型日和容量变量，如果保留大量二进制变量，规模会增大。当前容量规划使用连续变量，并通过效率损失、成本项和容量约束抑制无意义循环。后续如果要工程投产，可以重新加入充放电互斥、启停和爬坡等 MILP 约束。

### Q9：压力测试、随机规划、鲁棒规划有什么区别？

回答：

> 压力测试是固定基准容量，看它在不同扰动下表现如何；随机规划是把扰动概率纳入容量决策，最小化期望成本；鲁棒规划是不按概率平均，而是控制最坏场景成本。三者分别回答“现有方案抗不抗压”“长期平均最优怎么配”“最坏情况怎么保守配置”。

### Q10：怎么证明模型可信？

回答：

> 第一，物理约束上，电、热、氢平衡残差在测试中接近 0，SOC 和储氢都满足边界。第二，结果趋势符合工程直觉，比如碳约束收紧成本上升，需量电费提高会削峰，备用价值提高会增加燃料电池容量。第三，全项目有 68 个 pytest 测试，覆盖数据、模型、场景、容量规划、敏感性、不确定性和 v0.4 新机制。

## 22. 最后总结

当前 v0.4 项目的主线是：

```text
固定容量日调度：说明不同技术组合怎么运行
多典型日年化：把单日结果扩展到全年
容量规划：同时优化装多少和怎么运行
投资敏感性：检查设备成本假设是否改变结论
Pareto 分析：量化减排目标和成本之间的权衡
压力测试：评估固定容量方案面对不确定性的表现
随机规划：在概率意义下重新优化容量
鲁棒规划：控制最坏场景成本
v0.4 新机制：把设备真实运行、备用价值和电力市场机制纳入容量规划
```

你在秋招中要重点讲清：

1. 为什么综合能源系统要做电-热-氢-储耦合。
2. 怎么把工程系统抽象成变量、约束和目标函数。
3. 日调度和容量规划分别回答什么问题。
4. 设备投资成本、运行效率、备用价值、市场价格分别会影响哪些容量和运行结果。
5. 为什么燃料电池不能只看日常发电收益，还要看备用价值。
6. 为什么需量电费会强化削峰，为什么上网电价会影响风光装机。
7. 随机规划和鲁棒规划为什么不是重复分析，而是面向不同风险偏好的规划方法。

如果面试官只给 1 分钟，就讲：

> 我做了一个零碳园区电-热-氢-储优化项目，用 Pyomo 和 HiGHS 建了 MILP/LP 优化模型。项目先做 S0-S5 日调度，再做多典型日容量规划，之后加入投资敏感性、Pareto、不确定性、随机规划和鲁棒规划。v0.4 又补充了热泵 COP、电解槽和燃料电池效率、电池退化、燃料电池备用价值、可再生能源售电和需量电费。这个项目的核心价值是把经济性、低碳性、可靠性和市场机制放到同一个可解释优化框架里。
